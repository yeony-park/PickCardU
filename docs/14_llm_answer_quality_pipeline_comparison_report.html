LLM 답변 품질: 기존·구조 패키지와 Top3·Top5 비교

결론: 자동 점수의 raw best는 STRUCT-K3였지만 gate를 통과하지 못했다. 단일 custom Codex reviewer의 익명 packet 감사까지 합쳐 읽으면, production incumbent가 없는 개발 단계에서 정확성 우선 후보는 OLD 패키지이며 STRUCT는 추천형 질의 강점의 후속 후보로 남는다.

40 고유 질문 × 4 조합160 단발 응답gpt-5.6-terrastrict JSON개발 평가

왜 이 테스트를 했는가

검색 지표만으로는 부족하다

Top3·Top5에서 카드와 근거 청크를 더 잘 찾았다는 검색 결과가, 실제 LLM 답변의 카드 선택·수치·조건·인용 정확도를 보장하는지는 별도 확인이 필요했다.

무엇을 같은 기준으로 봤나

기존 OLD 패키지와 구조 STRUCT 패키지를 Top3·Top5 입력으로 각각 만들고, 같은 질문·같은 prompt·같은 JSON schema로 답하게 했다. 따라서 두 패키지 비교이며 청킹만의 인과 실험은 아니다.

160개 응답이 뜻하는 것

고유 질문 40개에 OLD-K3, STRUCT-K3, OLD-K5, STRUCT-K5 네 조합을 각각 한 번씩 실행해 40×4=160 응답을 만들었다. 예를 들어 같은 ‘배달·실적’ 질문을 네 입력 구성으로 답하게 한 비교다.

입력→답변→평가 흐름

40개 동결 질문→OLD 또는 STRUCT 카드 근거 그룹→K=3 또는 5→LLM strict JSON 답변→자동 점수 + 익명 packet 감사

OLD는 기존 검색·재정렬·근거 packaging 패키지, STRUCT는 구조 청킹·구조적 bundle과 그에 연결된 검색·재정렬·packaging 패키지다. K는 LLM에 줄 서로 다른 카드 근거 그룹의 최대 수이며, Top3/Top5 카드 선택과 근거 품질을 같은 질문 gold로 함께 비교했다.

실행 계약과 실제 prompt

모델은 gpt-5.6-terra, reasoning effort medium이며 strict JSON, store=false, tools 0, retries 0, single run으로 고정했다. 시스템 prompt와 user template은 아래 저장 파일의 원문 계약을 그대로 따른다.

실제 system prompt와 user template 보기
system_prompt:
너는 제공된 카드 근거만 사용해 질문에 답하는 도우미다. 근거에 없는 사실은 만들지 말고, 부족하면 insufficient_evidence를 true로 표시한다. 카드명·발급사·혜택·숫자·조건에 관한 모든 주장은 실제로 존재하는 evidence_id를 인용한다. 수치, 단위, 실적, 한도, 횟수, 제외 조건을 확대하거나 축약하지 않는다. 발급 가능성, 시장 전체에서의 최적성, 개인 자격 충족 여부를 주장하지 않는다. 근거가 충돌하면 summary와 claim에 충돌을 명시한다. 여러 카드가 조건을 만족하는 질문에서는 근거 순서를 유지하고, 질문의 모든 필수 조건을 근거로 확인한 카드만 포함한다. 지정된 JSON schema만 반환한다.

최종 해석과 다음 단계

production incumbent는 없으므로 switching cost를 적용할 수 없다. 자동 decision은 OLD 유지이고, blind audit에서도 OLD 11·STRUCT 7·동점 62/80이라 압도적 지배는 확인되지 않았다. 따라서 정확성 우선 개발 후보는 OLD 패키지, STRUCT는 recommendation에서 6 대 5 승 신호가 있는 후속 후보로 둔다. 이는 운영 승격 근거나 최종 확인셋 근거가 아니다.

다음에는 질문 최소 gold 보정은 결과 후 수정과 구분해 기록하고, 실제 사람 2인의 감사와 출력 정책 K를 먼저 고정해야 한다. 이후에는 (a) 개발에서 하나를 선택한 뒤 untouched 최종 확인셋으로 확인하거나, (b) 선택용·확인용을 분리한 평가 설계를 새로 고정하는 선택지가 있다. 어느 경우든 이번 결과를 본 뒤 조건을 바꿔 우승 구성을 만드는 방식은 피한다.
