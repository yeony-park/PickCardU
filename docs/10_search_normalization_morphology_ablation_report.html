왜 이 테스트를 했나

검색 정규화의 이득과 형태소 분석이 추가 이득을 주는지를 같은 질의로 분리해 확인하려 했다.

이 테스트로 무엇을 확인하려 했나

정규화 BM25·RRF와 형태소 후보가 혜택·조건 검색을 개선하면서 guardrail을 지키는지 확인했다.

검색 정규화와 Kiwi 형태소 ablation

13번 검색 정규화 테스트와 15번 Kiwi 형태소 후보 실험을 같은 개발 질의·같은 327개 계층 청크 기준으로 연결해, 유지할 후보와 아직 승격하지 않을 후보를 구분한 오프라인 retrieval 결과 보고서입니다.

판정. 13번의 정규화 후보는 evidence 20개에서 raw BM25 대비 Strict Hit@3, Recall@5, MRR@5, nDCG@5가 모두 상승했고, vector에 정규화 BM25를 RRF로 결합한 경우도 evidence 근거 순위 지표가 상승했다. 따라서 정규화 후보는 유지한다.
형태소 미승격. 15번의 현재 Kiwi 설정은 evidence RRF MRR@5 delta가 −0.004167으로 승격 기준 +0.025에 미달했고, Strict Evidence Hit@3와 nDCG@5 guardrail도 회귀했다. 따라서 현재 설정은 승격하지 않는다.

두 결과는 같은 개발 질의 30개(evidence 20개, card 10개)에서의 후보 비교다. 독립 holdout은 사용하지 않았으며, 운영 확정이나 미관측 질의 일반화를 주장하지 않는다.

범위와 비교 설계

10개 카드 fixture→327 계층 청크→30개 개발 질의→13번 정규화→15번 Kiwi 추가 ablation

13번은 검색 정규화 테스트 산출물이다. 원문·질의에 NFKC/lower/공백 정규화, 한글 2·3·4-gram, 수치·금액·퍼센트·기간 canonical token을 더한 BM25와, cache된 vector 순위를 비교했다. 15번은 13번의 normalized_bm25 및 rrf_vector_normalized를 정확히 재현한 뒤, 본문·질의에 Kiwi의 NNG/NNP/VV/VA 분석 token을 append하는 후보만 추가 비교했다. metadata·structured metadata·평가 필드는 형태소 순위 입력에서 제외했다.

실행·출처. 생성일은 15번 summary의 2026-08-18 UTC이다. 15번은 사용자 테스트 기록이 아니라 Codex coder agent가 실행해 남긴 산출물이다. 실행 환경은 skn25, nbclient 0.10.4이며, network/API 호출·새 embedding·패키지 설치는 각각 0회로 기록됐다.
공통 한계. BC는 selected excerpt, IBK는 incomplete/ambiguous fixture이며 나머지 카드도 기존 canonical fixture 범위를 벗어나지 않는다. 모든 구성은 structured-assisted chunk boundary를 공유하므로, 형태소가 본문만 읽더라도 청크 경계 자체의 영향을 분리하지 못한다.

Chroma integrity와 vector 재현성

실험확인 과정정직한 범위
13번 정규화최초 구현이 protected source에 직접 PersistentClient를 연결해 Chroma bookkeeping이 byte tree를 바꾸는 incident가 있었다. 이후 post-incident source의 byte-for-byte 임시 snapshot에서 cached query embedding으로 조회했고 published vector top-5는 30/30 exact였다.collection count 327·collection name·published top-5는 확인됐다. 그러나 incident 전 6–50위는 저장되지 않아 pre/post 전체 vector rank와 incident 전 RRF 동등성은 증명되지 않는다. 현재 13번 RRF는 post-incident snapshot 기반이다.
15번 형태소원본을 read-only로 확인한 뒤 NumPy exact squared L2로 먼저 재현을 시도해 20/30 top-5 exact를 얻었다. 근사 Chroma 순위와 완전히 같지 않아, byte-copied /tmp snapshot으로 fallback했고 30/30 top-5 및 normalized RRF summary exact를 확인했다.15번 vector 부분은 snapshot rank를 사용한다. NumPy exact L2가 published top-5 전체를 재현하지 못했다는 차이를 숨기지 않으며, 이 결과는 13번 incident 전 전체 순위의 증명이 아니다.
Metric guide: 이 표는 검색 정확도 결과표가 아니라 vector 입력·rank 재현성의 검증 기록이다. Pass 의미: stated snapshot에서 published top-5와 요약이 일치했다는 뜻이다. 핵심 한계: top-5 일치는 더 깊은 순위·다른 저장소 상태·운영 환경의 동등성을 보장하지 않는다.

최종 결과

정규화 후보는 유지하고 현재 형태소 설정은 미승격이다. 결과는 단일 개발 실행이며 운영 확정이 아니다. 본문 표와 근거 링크에 기록된 수치가 이 결론의 근거이며, 이 보고서 자체는 해당 고정 표본·계약에서의 비교 기록이다. 따라서 이 결과만으로 운영 채택을 확정하지 않고, 실패 사례와 범위 제한을 다음 평가의 입력으로 남긴다. 다음 단계에서는 같은 평가 계약을 유지한 채 필요한 원본 대조·독립 표본·후속 실험으로 결론을 다시 확인해야 한다.
