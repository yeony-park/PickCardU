왜 이 테스트를 했나

수기 정답셋으로 OCR 텍스트뿐 아니라 구조화 필드와 핵심 사실의 정확도를 확인하려 했다.

이 테스트로 무엇을 확인하려 했나

대상·조건·수치가 함께 맞는지, 단순 텍스트 유사도와 다른 위험을 드러내는지 확인했다.

2. 전체 OCR 텍스트 평가: gold/raw 기준

수치는 페이지별 결과의 단순 평균(macro average)입니다. 토큰 F1은 정규화한 토큰의 겹침 정도이고, CER(Character Error Rate)은 정규화 문자열의 편집 거리 비율입니다. CER은 예측 텍스트가 정답보다 크게 길면 1보다 커질 수 있습니다.

7. 지표 정의와 해석 한계

지표정의주의점
CER정규화 문자열 편집 거리 / gold 문자열 길이순서·삽입·삭제에 민감하며 1 초과가 가능합니다.
토큰 정밀도·재현율·F1정규화된 단어 토큰의 다중집합 교집합텍스트 내용 유사도는 보지만 읽기 순서와 문장 구조를 완전히 보지 않습니다.
수치 F1숫자·비율·금액 형태 토큰의 F1숫자의 문맥 연결이나 단위 의미가 완전히 맞는지까지는 검증하지 않습니다.
필드 exact match정규화 후 gold 필드 값과 예측 필드 값이 동일복합 객체·배열·표는 일부만 틀려도 전체 실패입니다.
엔진 일치두 엔진의 같은 필드 예측값이 동일둘 다 같은 오류를 낼 수 있으므로 정답 판정이 아닙니다.
현재 미포함 지표: 표 헤더·행·셀 단위 정확도, 필드별 부분 일치, 읽기 순서(LCS 등), 필드별 근거 위치 일치도는 아직 별도 산출하지 않았습니다. 현재 표 평가는 표 전체 exact match이므로, 실무에서 표 품질을 세밀하게 보려면 셀 단위 지표를 추가해야 합니다.

8. 결론과 다음 적용 기준

  • 전체 OCR 품질: 08의 8개 구성 재계산에서는 Upstage가 CER·토큰 F1, Codex CLI Luna가 수치 F1에서 가장 높았습니다. API 구성만 보면 Luna + original이 CER·토큰 F1, Terra + original이 수치 F1에서 가장 높았습니다.
  • 자동 통과: 전체 TXT 일치만으로 확정하지 말고, 엔진 간 수치 일치·핵심 필드 일치·gold 기반 검증을 함께 사용해야 합니다.
  • 필드 구조화: 두 OCR TXT를 같은 구조화기로 처리해 공정한 입력 비교는 가능해졌지만, 현재 39.32% exact match는 자동 확정에 사용하기에는 낮습니다.
  • 우선 개선: 핵심 필드부터 부분 일치와 근거 문장 검증을 추가하고, 표는 헤더/행/셀 단위 지표로 분해하는 것이 다음 단계입니다.
