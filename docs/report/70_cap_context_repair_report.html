왜 실행했고, 무엇을 고정했나

목적은 구조화 조회 실패, 잘못 적재된 값, 필요한 본문이 빠진 입력, 올바른 입력을 잘못 사용한 답변을 구분하는 것이다. 각 청킹의 검색 프로필은 이전에 선택한 운영 방식 그대로 유지했다. 두 프로필을 동일한 검색 설정으로 바꾸지 않았으므로 프로필 간 차이를 청킹 하나의 순수 효과로 해석하지 않는다.

최종 정리. 조회 표현과 평가 정책을 분리했고 DB cap 문맥 3행을 복구했다. 그러나 이번 JSON 근거·선택 지시문 결합 설정은 기존 순차보다 낮았으며 비용과 평균 답변 준비시간도 늘었다. 두 프로필 모두 기존 순차 개발 기준선을 유지하고 새 후보는 미채택한다. 운영은 그대로다. 올바른 입력의 주장·수치 연결 오류와 원문 반대 입력을 각각 고친 뒤, 미사용 질문으로 다시 확인하는 단계가 남았다.
