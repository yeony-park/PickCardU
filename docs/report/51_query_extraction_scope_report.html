51. 조건 추출 반복과 검색 범위 검사

2026-10-22 · 개발 질문 · 120조건 완료, 실패 복귀 포함 · 운영 미반영

40문항 × 3회 원래 추출 120조건을 완료했다. 스키마 통과 117회, 스키마 오류 2회, 외부 HTTP 520 오류 1회다. 별도 1회 진단 재시도는 성공했으며 원래 반복 행을 교체하지 않았다. 154개 사전 범위 검사에서 범위 이탈은 없었다. 의미 추출 정확성이 모두 검증됐다는 결과는 아니다.

실험 목적과 고정 조건

50번에서 고친 조회 계약을 LLM이 실제로 출력하는지, 40개 질문을 3회씩 추출했을 때 조건·결과 카드가 얼마나 달라지는지 검사한다. 카드 범위는 별도로 식별하며, 상세 설명 요청 때문에 조회를 건너뛰지 않는다. 후속 비교에는 사전 지정한 1회차만 사용한다. 2·3회차가 더 잘 나와도 교체하지 않는다. gpt-6-luna medium, 추출 출력 3,000, 네트워크 자동 재시도 0, 전체 8달러 상한을 고정했다. 원본 DB·운영 코드·OCR·청킹·색인은 수정하지 않았다.

지표 안내: 실행 수는 해당 회차에서 실제 요청과 체크포인트가 기록된 질문 수이며 예정 분모는 40이다. 카드 일치는 고정 조건으로 DB에서 카드가 한 개 이상 나온 질문 수다. 조회 결과 없음은 SQL을 실행했으나 전체 조건을 만족한 카드가 없는 경우이며 오답 판정이 아니다. 예를 들어 ‘철도’와 ‘기차’의 별칭을 추가하지 않으면 기차 질문은 0개일 수 있다. 상품 확인 필요는 존재가 확인되지 않거나 발급사·상품 구분이 모호한 질문이다. 추출 실패에는 스키마 검증과 외부 API 실패를 따로 기록한다. 이 표는 검색 정답률이나 최종 답변 정확도가 아니며 높고 낮음만으로 방식을 선정할 수 없다.

확인한 점과 실패 원인

H08(그린카드 v2 커피의 횟수·실적·한도), H11(넷플릭스와 유튜브), H18(동물병원)은 1회차에서 실제 DB 조회 후 각각 1·5·6개 카드가 일치했다. 50번의 수동 SQL 점검과 51번 LLM 추출은 동일한 조건을 강제로 사용하는 실험이 아니므로 카드 수가 다를 수 있다. 카드 수가 맞다는 이유만으로 추출 의미와 추천 품질을 검증했다고 해석하지 않는다.

1회차 H32는 실제 승인내역에서 남은 한도를 조회하라는 질문에 모델이 빈 혜택 대상을 가진 조건을 출력해 고정 스키마에서 거절됐다. 출력 토큰 초과가 아니며 원응답 상태는 completed였다. 이 회차를 더 잘 나온 결과로 바꾸지 않는다. 2회차 H17은 HTTP 520 서버 오류로 실패했다. 원응답에 usage와 응답 ID가 없어 실제 토큰·비용을 확인할 수 없다. 다음 호출은 비용 불명확 사유로 실행되지 않았다. 원인 불명 서버 오류를 청크 길이·토큰 부족으로 진단하지 않는다.

이후 사용자 지시로 원실패 상한을 차감하는 비용 예외와 별도 1회 재시도를 실행했다. 재시도는 7.567초에 성공했고 남은 원래 63조건을 재개했다. 원래 H17 2회차의 실패는 평가 분모에 남긴다. H32 2회차도 빈 대상 스키마 오류이며 3회차는 빈 외부 그룹으로 정상 출력했다. 원래 질문 40개 중 38개는 세 회차 카드 집합이 같았고 H03·H19가 달랐다. 모두 빈 결과인 질문도 같은 집합으로 세므로 이 수치는 정확도나 성능 동등성을 뜻하지 않는다.

H19 1회차는 시간에 따른 할인 설명을 unsupported 필터로 처리하고 다른 회차는 처리하지 않았다. H16 1회차에는 건당 고정 할인액 조건의 표현 누락이 있다. H12·D37의 월 커피 한도는 원문에 있지만 저장 숫자·기간 파생 속성으로 조회하기 어려운 한계가 남는다. 이 문제를 감추거나 원본 DB를 수정하지 않고 52번에서 현재 개발 시제품의 실제 실패 복귀를 포함해 비교한다. 스키마 통과율을 의미 추출 정확도라고 부르지 않는다.

비용과 중단 기준

이번 51번과 별도 재시도에서 확인된 비용은 $0.037290800이다. 이전 46–49번의 $0.234905430을 포함한 확인 비용은 $0.272196230이다. HTTP 520 1건의 실제 비용은 미확인이며 0달러로 처리하지 않았다. 입력 전체 바이트에 여유분 8,192를 더하고 출력 최대 3,000토큰을 적용한 기존 보수적 예약 계산은 이 요청에 $0.003127의 상한을 제시한다. 이는 실제 청구액이 아니다. 사용자 지시에 따른 별도 예외로 이 상한까지 차감한 예산 계상액은 $0.275323230이며, 이후에도 전체 8달러 및 원래 51번 0.4달러 한도를 지킨다. 다른 비용 미확인 요청이 생기면 다시 보호 장치가 중단시킨다. 별도 재시도 자체의 확인 비용은 $0.000346300이다.

확인 비용은 저장 usage에 일반 입력·캐시 읽기·캐시 쓰기·출력 토큰 단가를 적용한 계산값이다. 조직 실제 청구액은 미측정이다. 단가는 2026-10-22에 확인한 OpenAI 공식 가격표와 임베딩 모델 가격을 따른다. 이 단계에는 신규 임베딩 호출이 없다. 요청 수·실패·원응답은 캐시에 남아 있으며 실패 요청을 삭제하거나 비용 분모에서 제외하지 않는다.

최종 정리

상세 설명 요청이 있어도 DB 조회를 수행하는 사례를 실제 API 조건 추출에서 확인했다. 120조건과 범위 검사 154건을 완료했지만 의미 추출·DB 숫자 해석의 한계는 남았다. 오류를 숨기거나 좋은 회차로 바꾸지 않고 원래 1회차를 다음 비교에 사용한다. 스키마·서버 실패는 원래 설계한 복귀 경로로 평가에 남긴다는 검토 결과로 다음 개발 비교 진입을 허용했으며, 의미 추출 정확성이나 운영 준비 완료 판정은 아니다. 실패 포함 추출 평균은 6.002초이고 답변 출력 시간은 아직 미측정이다. 새 확인 비용은 약 0.03729달러, 미확인 상한을 포함한 전체 예산 계상은 약 0.27532달러다. 다음은 52번 네 검색 방식의 실제 검색·답변 비교다.
