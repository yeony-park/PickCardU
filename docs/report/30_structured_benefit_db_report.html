30. 기존 Upstage JSON → 구조화 검색 DB

OCR 검증기를 수정하지 않았습니다. Luna·Upstage OCR 통과를 가정하며 현재 Upstage 계층과 운영 청킹/검색을 사용합니다. 운영 원본·기존 산출물은 읽기 전용입니다. 이 결과는 구조화 검색 실험이며 PDF 사실 정확도나 운영 채택의 증거가 아닙니다.

실험 목적과 고정 조건

새 PC에서 구조화 선행 효과를 재현하고, benefit·parent-child 운영 프로필을 비교합니다. 기존 JSON을 DB에 적재하며 새 OCR 추출은 없습니다. 비구조화는 Vector:FTS5 BM25=0.4:0.6, 각 Top50, D20, 출력 Top3입니다. benefit는 selective BGE, parent-child는 모든 질문의 bundle BGE를 유지합니다. 프레임워크 없이 OpenAI SDK/Pydantic을 사용하고 새 LLM 호출은 gpt-6-luna/medium입니다.

Baseline / 이번 기준선 U는 기존 운영 알고리즘을 고정 Upstage corpus로 새로 구성한 개발 기준선입니다. 활성 운영 release의 기존 품질 수치를 가져온 것이 아닙니다. Candidate / 새 후보는 구조화 선행·카드 순위 융합이며 Production adopted / 운영 채택 설정은 없습니다. 이전 PC의 개선 관측은 사용자 기억으로만 남기고 이번 점수로 전용하지 않습니다.

운영 벡터 구현은 전체 검색에서 Chroma 근사 L2, 카드 범위 검색에서 메모리의 정확 L2를 사용합니다. 구조화 선행의 효과에는 카드 선별과 이 운영 범위 검색 방식이 함께 포함됩니다. 순수 DB 선별 효과와 동일하게 해석하지 않습니다.

무엇을 준비했는가

기존 Upstage normalized JSON의 사실·근거·원문을 그대로 보존하고 보수적인 수치 파생값만 추가했습니다. 구조화 검색은 SQLite 읽기 전용 SELECT로 읽은 facts에 같은 혜택 관계의 조건을 적용합니다. unknown은 false나 0이 아닙니다.

과정은 기존 OCR txt → 이미 저장된 normalized JSON → 새 SQLite facts 저장 → 질문을 고정 QueryPlan JSON으로 해석 → 같은 fact의 대상·할인율·실적·한도 조건 평가 → 후보 카드 안의 벡터+BM25 검색 → 근거를 전달한 별도 답변 생성입니다. 새 실험에서 txt를 다시 LLM으로 구조화하지 않았습니다. LLM은 SQL 문자열을 생성하지 않고 스키마의 값만 출력합니다. 이 소표본 실험은 읽기 전용 SQLite에서 읽은 사실을 Python의 AND/OR·unknown 판정기로 선별합니다.

주의점

원본 JSON provenance의 이전 모델·reasoning 기록은 보존했습니다. 새 실험 모델 설정과 혼동하지 않습니다. 다중 비율·금액·실적 구간·범위가 모호하면 unknown으로 남습니다. 범위·상한 비율 37건과 지출 상한을 혜택 한도로 오해한 90건은 독립 리뷰와 회귀 검증으로 unknown 처리했습니다. 월/일 한도 기간까지 확인된 사실은 66개입니다. 여행·커피 alias는 개발자가 고정한 사전이며 평가 결과를 보고 확장하지 않았습니다.

최종 정리

DB 변환과 읽기 전용 조회 기반을 준비했습니다. 구조화 검색 성능 개선은 후속 검색 결과로 판단합니다. OCR 승인·검증기 개선·운영 DB 교체는 하지 않았습니다.
