왜 실행했나

59번에서는 유효 카드 Hit@3가 높아도 중요조건까지 충족한 답변 비율은 낮았다. 명시 무실적이 unknown으로 남고, 일부 카드·발급사 범위가 누락되며, 무료서비스가 지원되지 않는 사례도 확인했다. 이번에는 같은 조건을 사용하면서 DB, 비교 술어, 원범위를 각각 바꿔 조회가 어느 단계에서 달라지는지 확인했다. 조건 추출기가 의도한 값을 만들었는지도 별도 판정했다.

무엇을 바꾸고 무엇을 고정했나

  • 56번 복사 DB에서 새 v3 복사본을 만들고 검색용 파생값만 교정했다. 운영·OCR 검증기·원본 PDF/JSON/DB·기존 실험과 색인은 보존했다.
  • 전월실적 없는 복합 문구와 명시적 무료이용·무료입장을 보완했다. 대상·동작·조건은 같은 원문 범위에 결속돼야 하며, unknown을 일괄 0으로 바꾸지 않았다.
  • 명시된 괄호·병렬 대상 표기와 카탈로그 상품·발급사 범위를 정리했다. 기차/철도 동의어·오타 보정·새 컬럼·별칭 사전은 추가하지 않았다. 일반 단어 ‘하나’나 ‘우리’만으로 발급사를 정하지 않는다.
  • 같은 106문서와 기존 두 청킹·임베딩·BGE·출력 한도를 유지했다. 조건·답변 지시를 최적화한 실험이 아니며, 후속 단계에서도 답변 지시는 기존 설정을 쓴다.
  • 기존 32질문의 조건 계획 96개를 검증해 재사용하고, 범용 추천 8질문에 대해서만 새 조건 추출 24회와 질문 임베딩 1배치를 실행했다.

기존 32질문은 결과를 이미 알고 있는 개발 질문이다. 새 8질문도 같은 문서에서 작성한 개발 평가다. 새 문서 홀드아웃이나 독립 사람의 맹검 평가가 아니며, 59번 통과율과 이번 추출 판정 비율을 직접 비교하지 않는다.

조건 추출은 올바른가

Schema/meaning PASS · 스키마 내 조건 의미 판정: 40질문×3회=120개 계획이 분모다. 명시 대상·동작·관계·지원 수치와 설명 요청을 적절히 구분한 수동 PASS만 성공으로 센다. 높을수록 좋지만 전체 질문 의미를 SQL로 모두 표현했다는 뜻은 아니다. 예를 들어 무료 요건을 unsupported_filters에 보존하면 보수적 정상 추출일 수 있지만 DB 조회는 0건이 된다. 부분 충족·실패를 제외하지 않으며, 조회 결과가 있다는 이유로 PASS를 주지 않는다.
