32. 두 운영 프로필 × 세 검색 방식

OCR 검증기를 수정하지 않았습니다. Luna·Upstage OCR 통과를 가정하며 현재 Upstage 계층과 운영 청킹/검색을 사용합니다. 운영 원본·기존 산출물은 읽기 전용입니다. 이 결과는 구조화 검색 실험이며 PDF 사실 정확도나 운영 채택의 증거가 아닙니다.

실험 목적과 고정 조건

새 PC에서 구조화 선행 효과를 재현하고, benefit·parent-child 운영 프로필을 비교합니다. 기존 JSON을 DB에 적재하며 새 OCR 추출은 없습니다. 비구조화는 Vector:FTS5 BM25=0.4:0.6, 각 Top50, D20, 출력 Top3입니다. benefit는 selective BGE, parent-child는 모든 질문의 bundle BGE를 유지합니다. 프레임워크 없이 OpenAI SDK/Pydantic을 사용하고 새 LLM 호출은 gpt-6-luna/medium입니다.

Baseline / 이번 기준선 U는 기존 운영 알고리즘을 고정 Upstage corpus로 새로 구성한 개발 기준선입니다. 활성 운영 release의 기존 품질 수치를 가져온 것이 아닙니다. Candidate / 새 후보는 구조화 선행·카드 순위 융합이며 Production adopted / 운영 채택 설정은 없습니다. 이전 PC의 개선 관측은 사용자 기억으로만 남기고 이번 점수로 전용하지 않습니다.

운영 벡터 구현은 전체 검색에서 Chroma 근사 L2, 카드 범위 검색에서 메모리의 정확 L2를 사용합니다. 구조화 선행의 효과에는 카드 선별과 이 운영 범위 검색 방식이 함께 포함됩니다. 순수 DB 선별 효과와 동일하게 해석하지 않습니다.
