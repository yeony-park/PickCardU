50. 구조화 조회 계약과 입력 경계 검사

2026-10-22 · 오프라인 개발 검사 · 유료 API 0회 · 운영 미반영

상세 설명 요청으로 DB 조회를 건너뛰는 문제와 기차/전기차 부분 일치를 재현하고 실험용 조회에서 수정했다. 독립 리뷰 후 보강한 회귀 12개와 전체 사실 3,403개의 토큰 경계 검사를 통과했다. 이 결과는 검색·답변 품질 비교 결과가 아니다.

왜 실행했는가

이전 49번은 대부분 질문이 DB 조회 전에 비구조화 검색으로 복귀했다. 이를 구조화 검색의 성능 저하로 해석할 수 없어, 조건 추출과 조회 처리부터 점검했다. 사용자 예시 8개와 기존 H01–H32를 개발 질문 40개로 동결했다. 이 집합은 신규 확인 집합이 아니다.

변경과 고정 조건

필터와 상세 설명 요청을 별도 필드로 분리했다. 횟수·한도·실적도 질문에서 수치 제한을 요구하면 필터가 된다. 같은 카드의 서로 다른 혜택 행으로 AND를 만족할 수 있도록 읽기 전용의 매개변수 SQL을 실행한다. 빈 내부 AND는 오류로 처리하고, 조회 결과가 없으면 원래 카드·발급사 범위에서 비구조화 검색을 수행한다. DB 오류는 검색 결과 없음과 구분한다.

BC와 IBK를 구분하고 기차가 전기차에 일치하지 않게 했다. 기차→철도 별칭과 오타 보정은 추가하지 않았다. H08의 저장된 기간 속성은 unknown이지만 한도 원문에 ‘통합 월 3,000원’이 있어 읽기 단계에서 명시된 기간만 해석한다. 원본 DB·운영 코드·OCR·두 청킹 프로필·색인과 BGE 토큰 한도는 유지했다.

지표 안내: Regression pass, 회귀 통과 수는 정의한 자동 검사 12개 중 성공한 수다. 최초 10개에 독립 리뷰에서 제안한 누락 필드·결제일 반례 2개를 추가했다. 높을수록 좋고 12개 모두 통과해야 다음 단계에 진입한다. 예를 들어 ‘커피의 월 몇 회인지’가 DB 조회까지 도달하면 해당 검사를 통과한다. 모든 사용자 질문의 추출 정확도를 의미하지 않는다. Eligible cards, 일치 카드 수는 해당 SQL 조건을 만족한 서로 다른 카드 수이며 많을수록 좋은 지표가 아니다. 예를 들어 철도·버스·택시 조건을 같은 카드가 만족하면 1개로 센다. 정답 카드 여부는 원문으로 따로 평가해야 한다. Token bound pass, 토큰 경계 통과는 자르지 않은 전체 사실과 가장 긴 개발 질문을 쌍으로 넣었을 때 문서/쌍 두 한도를 모두 만족한 사실 수다. 모든 3,403개가 통과해야 하며 사실 자체의 정확성을 검증하지는 않는다.

원문 확인

H08은 BC 그린카드 v2 PDF 4쪽에서 커피 10%, 전월실적 20만원, 월 2회, 통합 월 3,000원을 확인했다. H11은 NH 올바른FLEX PDF 2쪽에서 20%, 건당 7천원, 월 5천원, 가맹점별 월 1회를 확인했다. H21 PDF는 텍스트층이 없어 2쪽을 이미지로 직접 확인했다. 철도·고속버스·택시 5%, 일 1회·월 2회, 월 5천원, 전월 20만원과 택시 앱 결제 제외가 있다. 원문과 DB의 정보 존재를 확인했으며 OCR 검증기 수정은 수행하지 않았다.

최종 정리

조회 전 잘못된 복귀와 대상 오일치를 실험 경로에서 수정했다. 독립 리뷰에서 필수 필드 누락과 결제일 반례를 보강하고 기간 재해석은 한도 원문 자체로 좁혔다. 필수 검사에서 새 실패는 없었으며 자르지 않은 사실 직렬화는 기존 BGE 한도에 들어간다. 실험용 조회 계약을 다음 단계에 사용하고 이전 unresolved 기반 복귀 처리는 사용하지 않는다. 이번 비용은 0달러, 최종 오프라인 실행은 11.230초다. LLM 추출·답변 품질과 실제 응답 시간은 아직 평가하지 않았다. 다음은 51번 조건 추출·범위 검사이며, 운영에 채택한 설정은 아직 없다.
