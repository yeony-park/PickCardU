67. DB 표현·대상 매칭·질문 추출기를 분리해 확인

DB에 내용이 있어도 조회되지 않는 원인을 조사했다. 저장 계획 재생과 새 LLM 추출을 별도 단계로 비교했다. 최종 답변 생성·청킹 성능을 측정한 실험은 아니다.

왜 실행했나

‘반려동물 진료비’ 전체 문구와 DB의 ‘동물병원’ 표현이 달라 생기는 0건, 조건 본문에는 있지만 수치 파생 필드가 unknown인 경우, 질문을 조건으로 바꾸는 과정의 문제를 구분하기 위해서다. 미기재를 0원이나 무제한으로 바꾸지 않고, 같은 카드 안의 혜택 관계와 명시 조건을 유지하는지가 핵심이다.

원본 PDF·OCR·DB3·기존 결과는 보존했다. 각 청킹의 최적화 운영 검색 프로필도 변경하지 않았다. 67A는 저장 144계획을 고정했고, 67B는 같은 48원질문을 두 추출기에 각각 세 번 새로 보냈다.

1. 저장 계획으로 DB와 매칭을 교차 비교

원 DB3의 3,403개 사실은 SQLite와 JSONL의 원본·파생값이 전부 일치했다. DB4 사본에서는 같은 행의 명시 전월실적 금액과 출처가 일치하는 166행·35카드의 수치 파생값만 보완했다. 기존 0원, 원본 필드, 관계, 스키마는 보존했다. 범위·유예·연간·복수 금액·엄격 초과 등은 자동 보완하지 않았다.

2. 기존·수정 추출기를 같은 시점에 새로 비교

DB4·명시 명사 후보 매칭을 양쪽에 똑같이 적용했다. 원질문·모델(gpt-6-luna, medium)·스키마·출력 한도(3,000토큰)·기술 재시도 상한을 유지하고 호출 순서를 교차했다. 수정 지시문은 치과 진료비→치과, 반려동물 진료비→명시된 동물 범주 등 후보 대상의 입도를 안내한다. 새 동의어 교체·오타 보정은 하지 않았다. 지시문이 요청 필드에도 영향을 줬으므로 결과는 추출 지시문 전체 효과로 해석한다.

Question-plan semantic completeness — 질문 계획 의미 충족률: 수동 계약을 충족한 PASS/추출기별144계획. 질문별 세 번 평균을 48질문 사이에서 평균한 값과 같다. 높을수록 좋다. 대상·행위·숫자·AND·제외·요청 정보의 보존을 직접 읽고 채점했고 코드는 요청·판정 결속을 검증했다. 예: 개인25만원을 상품 WHERE로 만들면 안 된다. 5. 설정 선택과 다음 검증

68번 개발 후보: DB4 + 명시 명사 후보 매칭(projected) + 기존 추출기(old). 수정 추출기는 R09 세 번째 회차에서 기존에 보존한 무료·공항 조건을 잃어 무회귀 승격 기준을 충족하지 못했다. 독립 검토와 main 검토를 거쳐 승격을 거절하고 기존 추출기를 유지했다. 기존의 오류2건도 남아 있으며 기존이 더 우수하다는 결론은 아니다. 답변 점수를 설정 선택에 쓰지 않았다.
