48. 원질문을 보존한 구조화 검색 보조

2026-10-21 · 개발 실험 · 두 프로필 모두 기존 A를 유지한다. 구조화 단서로 일부 조건을 보완했지만 기존 중요조건이 빠진 사례도 확인했다. 원질문 검색을 먼저 유지해도 최종 후보와 근거가 바뀌면서 조건을 잃을 수 있었다. 운영 적용은 하지 않았다.

왜 실행했나

45번은 검색 이후 구조화 근거를 답변 입력에 다시 넣는 비교였다. 이번에는 구조화 DB에서 실제 일치한 혜택·조건을 검색 단계의 보조어로 활용했다. 41·42번의 질문/별칭 보강과도 구분한다. 새 질의 생성 LLM은 사용하지 않았고, 답변 LLM에는 세 방식 모두 원질문과 검색 근거를 전달했다.

A는 원질문으로 Vector/BM25 각각 50개를 검색한다. B는 A의 원질문 성분을 그대로 보존하고 같은 카드 범위에서 보조어로 각각 50개를 추가 검색한다. 두 경로를 성분별 동일 가중치 RRF(순위 역수 결합)로 합친 뒤 기존 검색 결합·원질문 재정렬을 사용한다. A_budget은 원질문으로 각각 100개를 검색하는 예산 대조군이다. 최종 후보 20개·카드 3개·카드별 근거 최대 5개·입력 64,000바이트는 동일하다. A_budget은 조회 후보 수 대조군이며 임베딩·중복·CPU 비용까지 같은 조건은 아니다.

47번의 전체 복귀 A를 고정하고 기존 개발 질문 48개 × 두 운영 프로필 × 세 설정, 288개 논리 답변을 비교했다. 문서·청크·문서 임베딩·모델 gpt-6-luna·reasoning medium·답변 출력 상한 2,400토큰을 유지했다. parent-child는 기존 budget5(토큰 기준 안에서 청크 묶음 최대 5개)를 사용했다. 운영 소스는 읽기 전용으로 재사용했다.

보조어를 쓸 수 있었던 범위

구조화 전체 조건에 일치하고 45번 원문-청크 연결에서 확인된 fact 중, 원문 문자 위치까지 다시 맞는 필드만 사용했다. 각 혜택의 대상·값·조건은 같은 ‘혜택 묶음’ 안에 유지했다. 전체 fact 단위로 4,096바이트 한도를 적용했고 실제 최대는 1,294바이트였다. 과거 verified 표기에도 문자 위치가 맞지 않는 4건은 제외했다. 원문·DB·과거 결과는 수정하지 않았다.

보조 적용은 benefit 23/48, parent-child 9/48, 합계 32/96이었다. 나머지에서는 B가 A를 그대로 사용했다. 구조화 1차 카드 선정과 별개로, 보조어 승인 범위에는 프로필별 출처 연결 검증 차이가 있다. 이 비교를 순수 청킹 우열이나 전체 DB 정확도로 해석할 수 없다. 출처의 문자 일치도 모든 혜택 관계의 의미 정확도를 보장하지는 않는다.

전체 조건의 자동 진단

아래는 기존 42번의 부분 정답 목록을 그대로 사용한 진단값이다. 실제 정답률이나 원문 조건 완전성으로 읽으면 안 된다. 예를 들어 E04의 taptap DIGITAL 멜론 50%와 E41의 Point Plan 계열 통신 적립처럼 목록 밖 유효 카드도 있다. 원점수는 보존하고 별도의 원문 판단으로 구분했다. 최종 선정은 중요조건 손실 기준으로 판정했다.

지표 안내: Hit@3(상위 3개 정답 포함)은 사전 양성 정답이 있는 44질문 중 정답 목록 카드가 상위 3개에 한 장이라도 포함된 질문 수다. MRR(첫 정답 순위 역수 평균)은 같은 44질문에서 1위=1, 2위=1/2, 3위=1/3, 없음=0을 평균한다. Known-positive answer match(자동 정답목록 일치)는 해당 목록과 고정 혜택 규칙을 답변이 충족한 질문 수다. 모두 높을수록 좋고 개별 질문은 규칙 일치 시 1이다. 예를 들어 올바른FLEX가 2위면 Hit는 1, 순위 점수는 1/2다. 목록 밖 유효 카드·문장 의미·실적/한도 누락은 이 값만으로 판별하지 못한다. 하위유형 분모는 수치 16, 고유명사 16, 의미 양성 12이며, 의미 질문 중 나머지 4개는 양성 정답을 지정하지 않아 제외했다.

질문별 변화와 후보 손실

지표 안내: 아래 개선/악화/동률은 위 자동 일치의 질문별 0/1을 A와 비교한 값이며 실제 품질 승패가 아니다. 분모는 양성 44질문이다. Candidate loss(후보 손실)는 A의 최종 재정렬 후보 20개 또는 카드 상위 3개에 있던 사전 정답 카드가 사라진 질문 수다. 낮을수록 좋고 새 중요 손실 0이 보존 기준이다. Evidence changed(근거 변경)는 48질문 중 근거 목록이 달라진 질문 수로, 변화 자체에는 좋고 나쁨의 방향이 없다. 예를 들어 원질문 검색에 있던 올바른FLEX가 결합 뒤 후보 20개에서 밀리면 후보 손실로 센다. 다른 유효 카드가 대신 들어올 수 있어 정답 목록 손실과 실제 요구 미충족은 구분해야 한다.

직접 원문과 대조한 선정 근거

근거가 바뀐 B 출력 27쌍을 A/A_budget와 비교해 살펴보고, 선정에 영향을 주는 아래 7개 사례를 원문까지 집중 대조했다. 모든 새 답변의 모든 문장을 사람처럼 전수 심사한 정답률은 측정하지 않았다. 이 개발 단계는 알려진 중요조건 손실이 하나라도 있으면 B를 미선정하는 사전 기준이므로, 확인한 손실만으로도 유지 결정을 내릴 수 있다.

판정 안내: Important-condition loss(중요조건 손실)는 기존 답변/근거에 있던 이용 가능 여부·대상 이용금액·실적·한도 같은 핵심 조건이 새 결과에서 사라지는 경우다. 낮을수록 좋고 새 손실 0이 통과 기준이다. 예를 들어 주유5% 할인과 실적조건만 남고 ‘발급 첫달에는 제공하지 않음’이 빠지면 첫달 이용 가능 여부를 오해할 수 있다. 판단 시 요약문·주장 본문·조건 배열·추천 사유를 모두 확인한다. 아래는 발생률 추정이나 독립 사람 평가가 아닌 출처를 확인한 사례 판단이다. 독립 리뷰에서 E06 오판을 발견한 뒤 전체 출력 기준으로 E14·E40·E34·E39·E06을 재확인했다. 최초 실행 자원은 별도 보존한다. 전체 오프라인 재실행의 시간·검증 결과는 completion_status.json에 별도로 기록하며, 최초 실행 지연을 재개 시간으로 덮어쓰지 않는다. HTML은 원자료를 확인한 뒤 직접 작성했다.

최종 정리

구조화 보조가 일부 조건을 찾는 데 도움이 됐지만, benefit의 출력 조건 누락과 parent-child의 근거 조건 손실이 있어 두 프로필 모두 B를 미선정했다. A_budget의 일부 원점수 개선도 자동 채택하지 않았다. 추가68요청에 약0.0990달러, 전체 약29분이 들었다. 49번에서는 조건 추출·실패 경계 + 구조화 카드 선정 + 원질문 비구조화 검색을 고정하고, 새32질문에서 현재 비구조화 기준과 신규 반복 비교한다. 운영 이식 적격 여부는 그 확인 결과로 판단하며 운영 코드는 계속 변경하지 않는다.
