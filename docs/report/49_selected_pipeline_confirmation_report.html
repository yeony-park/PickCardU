49. 새 질문으로 확인한 구조화 검색 후보

2026-10-21 · 같은 106문서의 새 32질문 · 첫 회차 확인 · 두 청킹 모두 운영 이식 적격 판정을 보류한다. 후보의 요구 충족 수는 늘었지만 중요한 조건 누락이 새로 확인됐다. 사전에 정한 중단 규칙에 따라 남은 두 회차를 실행하지 않았다. 운영 코드는 변경하지 않았다.

왜 실행했나

46번에서 조건 추출의 실패 경계를 확인하고, 47번에서 구조화 일부 일치 시 전체 비구조화 검색으로 복귀하는 방식을 유지했다. 48번에서는 구조화 근거로 검색을 보조하는 B 대신 원질문 검색 A를 두 프로필 모두 유지했다. 이번에는 그 개발 후보가 새 질문에서도 기준보다 나아지고 중요한 조건을 보존하는지 확인했다. 앞선 개발 결과와 이번 확인 결과는 별도다.

U는 현재 운영 검색 방식에 해당하는 비구조화 기준이다. 원질문으로 Vector+BM25 검색과 기존 재정렬·답변 생성을 수행한다. S는 개발 후보다. 질문을 고정 스키마로 추출하고 구조화 조건 전체를 만족하는 카드 범위를 찾은 뒤, 그 범위 안에서 원질문으로 같은 비구조화 검색을 수행한다. 구조화 실패·일부 일치·미해결 조건은 명시 카드 범위를 보존하여 U로 복귀한다. 정확한 카드가 불분명한 스카이패스 질문은 추가 확인을 요청한다.

48번에서 유지한 A는 S 안의 비구조화 검색 설정 이름이다. 이번 기준 U와 같은 이름이 아니다. 45번의 구조화 근거 직접 추가, 47번의 일부 일치 카드 우선 검색, 48번의 구조화 검색 보조어는 모두 사용하지 않았다. S가 구조화로 선정한 것은 카드 범위이며, 구조화 DB의 혜택 문장을 답변 LLM에 추가로 넣지 않는다.

무엇을 바꾸고 무엇을 고정했나

같은 질문에서 U와 S를 비교했다. 청킹은 운영의 benefit 및 parent-child 프로필을 그대로 사용했다. 후보 20개·카드 상위 3개·카드별 근거 최대 5개·입력 64,000바이트·Vector/BM25 가중치 0.4/0.6·parent 묶음 budget5를 고정했다. gpt-6-luna, reasoning medium, 조건 추출 출력 3,000토큰, 답변 출력 2,400토큰이다. 원질문은 검색·재정렬·답변 입력에 보존했다. 문서 청크나 문서 임베딩은 새로 만들지 않았다.

32질문 × 두 프로필 × U/S × 신규 생성 3회를 계획했다. 질문은 고유명사·수치/조건·의미/혜택·부정/진단 각 8개다. 첫 회차 이후 원문 대조에서 새 중요 오류가 확인되면 해당 프로필의 남은 두 회차를 중단하도록 실행 전에 정했다. 각 방식·회차의 답변을 새로 생성하고, 검색·질문 벡터만 입력 해시로 재사용했다. 첫 회차에는 U/S 실행 순서를 번갈아 배치했다.

새 질문과 주석 초안은 48번 결과 선정 전에 작성했다. 다만 같은 문서·같은 작성자의 질문이며 새 PDF나 독립 사람 평가 자료는 아니다. 필수 의미를 사전에 기록했으나 대체 카드의 유효성은 일부 실행 뒤 원문으로 추가 판정했다. H23의 NH 대체 카드 해석은 답변 검토 전에, H21의 OILPASS 해석은 답변을 읽은 뒤 보완했다. 질문·모델·검색 설정은 바꾸지 않았다. 전체 64쌍을 방식명 숨김 상태로 읽었지만 카드 범위나 H23 원문 대조로 방식을 추론할 수 있어 완전한 맹검으로 보지 않는다.

Upstage가 OCR 검증을 통과했다는 기존 실험 가정을 유지했다. OCR 검증기·제목 계층은 수정하지 않았다. 아래 H23에서는 제목과 본문의 연결이 정확하다는 가정에 어긋나는 한 사례가 발견돼 별도로 공개한다. 한 PDF 대조가 전체 OCR 검증을 대신하지는 않는다.

실행된 범위와 검색 경로

지표 안내: Executed conditions(실행 조건 수)는 실제 저장 답변의 수다. 분모는 계획한 논리 조건 수이며, 미실행을 실패나 동률로 세지 않는다. Route count(검색 경로 수)는 첫 회차 조건 추출 32질문을 분모로 실제 선택한 경로를 센다. 경로 비율 자체에는 높고 낮음의 품질 방향이 없다. Parser success(추출 요청 성공)는 유효 스키마 저장 여부이고 의미·DB 일치 성공과 다르다. 예를 들어 커피는 추출했지만 신청 절차를 미해결로 남기면 정상 추출이어도 U로 복귀할 수 있다. Mandatory regression(필수 회귀 통과)은 고정 9사례에서 예상 경계 행동을 모두 유지해야 통과하며, 새로운 모든 질문의 정확성을 보장하지 않는다.

질문별 개선·손실과 조기중단 근거

지표 안내: Paired wins/losses/ties(질문별 개선·손실·동률)는 이번 한 회차 PASS 여부를 0/1로 바꿔 같은 질문의 U/S를 비교한 진단값이다. 프로필별 32질문이 분모다. 실제 구조화 검색 두 질문과 원문 관계 확인

H22는 온라인서점·병원·약국의 Discount Plan+ 카드를 구조화로 선정했다. benefit은 U/S 모두 필수 설명을 충족했고 parent-child는 양쪽 모두 실적·월한도 설명이 부족했다. H23은 영화와 운동 혜택에서 NH 올바른NEW WONDER를 선정했다. parent-child S는 U가 못 찾은 두 혜택을 찾아 FAIL→PARTIAL로 나아졌으나 ‘할인 PACK 선택’ 조건이 빠졌다. benefit도 양쪽 모두 그 선택 조건이 부족했다. 이번 실제 구조화 두 사례에서 구조화 검색만의 새 완전 PASS 증가는 확인하지 못했다.

H23의 DB에는 영화 10%·헬스 5%와 함께 condition: '할인 PACK' 전월실적 …가 저장돼 있었다. PDF 2쪽은 왼쪽 할인 PACK, 오른쪽 적립 PACK의 두 열이다. 그런데 parent 검색 근거 한 묶음은 경로·제목이 ‘적립 PACK’인 상태로 ‘특화영역 청구할인’과 월 할인한도 표를 포함했다. 이 한 사례에서는 부모 제목과 실제 혜택의 관계가 정확하다는 가정을 유지할 수 없다. PDF의 열 구분과 평탄화된 텍스트 순서가 다르다.

DB에 조건이 정확히 있어도 카드 범위만 넘긴 다음 검색·생성에서 그 조건이 최종 답변까지 보존된다는 보장은 없었다. 그렇다고 45·48번의 전체 근거 추가/보조어를 다시 채택할 근거도 아니다. 다음 개발 검증은 원질문 검색을 유지하면서 DB의 중요한 적용조건과 최종 답변을 대조하는 제한적 보완이 효과가 있는지, 기존 조건 손실을 만들지 않는지 확인하는 방향이 적절하다. 이번 승인 범위에서는 구현하지 않았다.

API 실패·재시도와 실행 오류

최종 저장 답변 128개는 모두 정상 복원됐다. 그러나 처음부터 모든 API 요청이 성공한 것은 아니다. H22 benefit U는 출력 2,400토큰 중 reasoning 1,831토큰을 사용한 뒤 JSON이 끝나지 않아 첫 요청이 실패했다. 기존 답변 생성기의 한 번 재시도로 같은 2,400 상한에서 성공했다. H32 parent U는 첫 API의 JSON 스키마는 통과했지만 카드와 근거 인용의 소속이 섞여 운영 복원 검사가 거절했고, 한 번 재시도해 성공했다. 두 추가 요청과 실패 요청 비용도 모두 포함했다. 네트워크 자동 재시도는 0이다.

첫 준비 실행에는 공통 검증기가 요구하는 매니페스트 별칭 max_output_tokens 누락으로 중단되는 실행 오류도 있었다. 당시 질문 임베딩 한 배치와 H01 추출 한 건은 이미 저장돼 있어 재전송하지 않았다. 원래 실패 노트북·매니페스트를 별도 보존하고 parser_output=3000과 같은 별칭만 추가했다. 실제 저장 요청으로 수정 전 실패·수정 후 통과를 오프라인 확인했다. 질문·모델·검색 정책·토큰 상한은 바꾸지 않았으며 이 오류를 검색 성능 실패로 세지 않았다.

비용과 응답시간

자원 지표 안내: Physical requests(실제 요청 수)는 저장한 외부 요청이며 실패·재시도도 포함한다. Cost(계산 비용)는 요청별 저장 usage에 46번에서 같은 날 확인해 보관한 공식 USD 단가를 곱한 값이다. 실제 청구액·세금은 미측정이다. API latency(요청 지연)는 API 시도별 벽시계 시간이며 재시도 포함 논리 답변 시간과 다르다. Mean은 실제 관측 수 n의 산술평균, median은 중앙값, P95는 정렬한 ceil(0.95×n)번째 값이다. 예를 들어 실패 24초 뒤 재시도 11초라면 요청은 2건이고 답변 생성 단계는 약35초다. 낮을수록 자원 측면에서 유리하나 품질 통과를 대신하지 않는다. 임베딩 개별 API 지연은 미측정이다.

최종 정리

S는 두 프로필 모두 첫 회차 필수 요구 충족 수가 두 질문 늘었지만 각 프로필에 PASS 손실 한 질문이 있고, 별도 원문 검사에서도 새 중요조건 누락이 확인됐다. 같은 근거에서의 생성 차이와 실제 구조화 두 질문의 효과를 구분해야 한다. benefit이 이번 원점수에서는 높았으나 청킹 우열·검색 방식의 일반적 우월성은 확정하지 않았다.

46의 경계 검사, 47의 전체 복귀, 48의 원질문 검색 설정은 개발 후보 구성으로 유지한다. 부분 일치 카드 우선 검색·구조화 보조어·예산 대조군은 채택하지 않았다. 최종 S의 운영 이식은 두 청킹 모두 보류하며 현재 비구조화 운영 코드는 그대로다. 첫 회차 확인은 완료했고 나머지 두 회차는 계획된 조기중단으로 미실행이다. 약0.111달러·53분의 추가 실행이 들었으며 누적은 약0.235달러다.

다음 검증은 중요한 적용조건이 근거에 있는데도 답변에서 빠지는 문제와 H23의 혜택 묶음 관계를 다뤄야 한다. 개선안을 개발 자료에서 검증한 뒤, 수정에 사용하지 않은 질문으로 다시 확인해야 운영 이식 적격을 판단할 수 있다. 현재 32질문을 보고 수정한 설정을 같은 자료에서 다시 통과시켜 최종 확인으로 부르지 않는다.
