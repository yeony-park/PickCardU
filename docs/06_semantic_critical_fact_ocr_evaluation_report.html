반복 비교표의 “Fact exact 평균”은 각 실행의 fact exact 비율을 평균한 값이다. “± 표준편차”는 동일 모델을 반복 실행했을 때 결과가 얼마나 흔들렸는지 나타낸다.

수치 정확도는 모든 중첩 사실 내부의 숫자만 비교한다. exact 지표는 대상·조건·수치·정답에 기록된 단위까지 모두 일치해야 통과한다.

해석

핵심 수치 보존은 두 엔진 모두 높다. Vision은 4개, Upstage는 10개의 수치 leaf에서 정답과 달랐다. 따라서 금액·할인율·횟수 오류 탐지에는 수치 정확도를 핵심 지표로 사용할 수 있다.
  • 전체 fact exact가 더 낮은 이유는 금액만 맞아도 통과하지 않기 때문이다. 예를 들어 대상 업종, 전월실적, 할인 한도 또는 단위 표현이 다르면 실패한다.
  • 수치 정확도만으로는 “편의점 1만 원”이 “숙박 1만 원”으로 바뀐 오류를 잡지 못한다. 이 경우 의미 필드 exact가 실패해야 한다.
  • 현재 단위는 기존 수작업 라벨의 enum을 그대로 비교한다. won과 KRW처럼 의미가 같은 표기를 정규화하는 후속 작업이 필요하다.

다음 단계

  1. critical fact를 대상 + 조건 + 수치 + 단위의 공통 스키마로 수작업 정규화한다.
  2. 단위·금액·비율 표기를 공통 enum으로 정규화한 뒤, 단위 불일치와 실제 의미 오류를 분리한다.
  3. 수치가 맞지만 대상·조건이 다른 사례를 unsafe mismatch로 별도 집계해 검증 파이프라인의 실패 기준으로 사용한다.

산출물

  • 의미 기반 정답셋
  • 요약 JSON — 현재 워크스페이스에 원본 산출물 미보존
  • 사실별 상세 CSV — 현재 워크스페이스에 원본 산출물 미보존
  • 실험 노트북

보고서 수치는 기존 실행 기록이며, 현재 워크스페이스에 원본 산출물이 보존되지 않아 직접 재검증이 제한된다.

표준편차는 두 실행의 모집단 표준편차다. Upstage는 기존 OCR 원문을 한 번 구조화한 기준선이므로 반복 분산을 비교할 수 없다.

  • Luna는 핵심 수치 정확도 평균이 가장 높았지만 fact exact 변동 폭이 더 컸다.
  • Terra는 fact exact·문자 leaf 정확도가 Luna보다 높고, 두 번의 결과 변동도 더 작았다.
  • 두 모델 모두 Upstage보다 수치 정확도는 높았으나, 전체 fact exact의 차이는 작다. 반복 수가 2회이므로 우열을 확정하지 않는다.

추가 복구 실행 중 API 크레딧 소진으로 Terra 2차의 한 카드가 완료되지 않았다. 해당 미완료 run은 보존하지만 위 평균·표준편차에는 포함하지 않았다.

최종 결과

이 보고서는 semantic critical fact 기준에서 98.52와 96.30의 반복 비교 결과를 기록한다. 결과는 대상·조건·수치를 함께 보는 사실 단위를 이후 관계형 평가의 입력으로 삼는 역할을 했다. 현재 워크스페이스에는 원본 일부 산출물이 미보존되어 수치를 직접 재검증하는 데 제한이 있다. 그래서 후속 관계형 평가는 저장된 gold와 기존 실행 근거를 분리해 다뤘다.
