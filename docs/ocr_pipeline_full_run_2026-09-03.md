### 3.3 OCR 품질 진단

최종 106개 결과를 동일한 Upstage 출력과 비교했다. Upstage는 정답표가 아니라 차이를 찾기 위한 고정 비교 대상이다.

| 지표 | 최종 결과 | 해석 |
|---|---:|---|
| Luna 본문 문자 수 | 891,444 | 실제 빈 면 정규화 후 106개 전체 합계 |
| 평균 문서별 token Jaccard | 0.850596 | 양쪽 OCR의 단어 겹침 진단값 |
| Upstage 숫자 기준 Luna 숫자 재현율 | 0.962503 | Upstage 숫자 중 Luna에도 있는 비율 |
| 페이지 배열 무결성 | 617/617쪽 | 누락·중복·순서 오류 0건 |
| 비어 있는 비-빈 페이지 | 0쪽 | 구조화 차단 조건 해소 |

**지표 설명**

- `token Jaccard`는 Luna와 Upstage에서 나온 서로 다른 단어 집합의 겹침 비율이다. 예를 들어 둘 다 `편의점 10% 할인`을 읽으면 높아진다. 먼저 한 문서 안의 페이지 값을 평균하고, 다시 106개 문서의 값을 평균했다. 높을수록 두 OCR이 비슷하지만, 둘 다 같은 오독을 해도 높을 수 있어 정답률은 아니다.
- `숫자 재현율`은 Upstage가 읽은 서로 다른 숫자 중 Luna에도 있는 비율이다. 예를 들어 Upstage의 `전월 30만원, 월 1만원` 중 Luna가 두 숫자를 모두 읽으면 100%다. Upstage가 휴대전화 화면이나 디자인 속 숫자를 잘못 읽으면 Luna가 정확해도 낮아질 수 있다.

상세 프롬프트의 전반적인 OCR 정확도가 향상됐다고 단정할 수는 없다. 사람 검수용 gold가 없고 Upstage도 오독할 수 있으므로 위 수치는 진단용이다. 이번 단계의 통과 기준은 두 OCR의 완전한 일치가 아니라, 106개 문서의 페이지 무결성과 구조화 전에 자동 검출 가능한 빈 본문·빈 면 오류가 없는 것이다.

**지표 설명**

- `grounding 자동 통과`는 두 lane 모두에서 모든 카드명·혜택 필드·근거 인용·줄 분류가 자기 OCR에 연결된 문서 비율이다. 예를 들어 `편의점 10% 할인`이라는 fact가 있으면 같은 lane OCR의 정확한 인용문에서 `편의점`, `10`, `%`를 확인할 수 있어야 한다. 높을수록 좋고 문서 하나라도 위반하면 그 문서 전체가 통과하지 않는다. OCR이 맞더라도 구조화 모델이 제목의 의미를 fact에 옮겨 적으면 현재의 문자 단위 규칙에서 실패할 수 있다.
- `검토 필요`는 사람이 보거나 구조화 계약을 수정해야 하지만 원본을 버리지 않은 상태다. 오류가 확정됐다는 뜻은 아니다. 예를 들어 `target`이 빈 문자열인 사실이나, target이 근거 문장에는 없고 바로 위 제목에만 있는 사실이 포함된다.
- `구조화 재실행 필요`는 할인·적립·조건처럼 혜택일 가능성이 있는 OCR 줄을 구조화 모델이 `ignore`로 넘긴 경우다. 누락 위험이 커 자동 승인하지 않는다. 반대로 전화번호나 날짜가 규칙에 잘못 걸리는 오탐 가능성도 있으므로 차단된 7개가 모두 실제 혜택 누락이라고 단정할 수 없다.
- `JSON 대 JSON 관계 비교`는 Luna와 Upstage가 만든 fact tuple의 일치 여부다. 예를 들어 양쪽 모두 `편의점 / 전월 30만원 / 10 / % / 월 5천원`을 만들면 일치한다. 이번에는 앞선 grounding 통과 문서가 없어 분모가 0이므로 0%라고 기록하지 않고 `미측정`으로 표기한다.
