사용자 익명 A/B 답변 평가

결론: 사용자 평가 15건 중 제외 1건을 빼면 STRUCT 5승·OLD 4승·동점 5건이다. 새 구조의 약한 신호는 있지만, 동점이 많고 단일 사용자·개발 질문의 소표본이므로 승자를 확정하지 않는다.

사용자 직접 평가익명 A/BTop3 9건 + Top5 5건저장 응답 재사용

왜 이 평가를 했는가

자동 점수 다음의 확인

25번 자동 답변 품질 비교는 구성 차이를 수치화했지만, 실제 사람이 두 답변을 읽을 때 어느 쪽이 더 정확하고 이해하기 쉬운지까지 확정하지는 못했다.

A/B가 뜻하는 것

A와 B는 OLD·STRUCT의 고정 별명이 아니다. 질문마다 무작위로 배치했으며, 평가 뒤 배정표를 열어 실제 구성을 해제했다. 따라서 A 또는 B 자체의 승수를 합산하지 않는다.

비교한 패키지

OLD는 기존 card/page/section/benefit 청킹, 선택적 BGE 질의 경로, 안전한 제목 보강을 묶은 패키지다. STRUCT는 구조형 parent/child 청킹, 자동 근거 묶음, 전체 질의 BGE를 묶은 패키지다. 25번 contract·manifest 범위상 청킹 하나만의 인과 비교가 아니다.

무엇을 확인하려 했는가

각 질문에서 카드 선택, 필수 혜택·숫자·조건, 실제 인용 근거, 누락·unsupported claim·response failure를 보되, 사용자는 먼저 익명 A/B만 보고 판단했다. 아래는 packet JSON의 summary, cards, 중요한 조건(claim)을 사람이 읽는 형태로 배치한 것이며, 원문 JSON 전문과 문장별 전체 근거는 하단 JSONL 링크에서 확인할 수 있다.

해제 뒤 사용자 평가 집계
입력 KOLD 승STRUCT 승동점비고
Top333310번 제외 후 9건
Top51225건
합계455평가 15건 중 10번 제외
비교 데이터·분모: 사용자가 직접 판정한 15개 익명 pair 중 의도 모호로 제외한 10번을 뺀 14개다. 성공 의미: 같은 K 안에서 더 명확하고 근거에 맞는 답이 승리다. 핵심 한계: 승·패는 사용자 한 명의 요약형 표시 판단이며 반복·다중 평가자 평균이 아니다. 카드 예: Top5에서 STRUCT가 여러 카드를 더 정확히 보여도, Top3의 첫 세 카드 선택은 OLD가 더 나을 수 있어 K별로 분리한다.
