왜 이 테스트를 했나

OCR 뒤 만든 계층 청크에서 카드 혜택 근거를 실제로 찾을 수 있는지 기준선을 만들려 했다.

이 테스트로 무엇을 확인하려 했나

keyword·vector·RRF가 카드 상품과 혜택·조건 근거를 Top5 안에 얼마나 앞세우는지 확인했다.

Hierarchical Chunking Retrieval

카드 혜택 gold fixture를 계층 청크로 만들고, 키워드·벡터·RRF 검색과 ablation을 비교한 오프라인 retrieval 평가 보고서입니다.

목적과 범위

이 실험은 10개 카드의 gold raw TXT와 gold structured JSON만으로 만든 canonical fixture에서, 카드 혜택 근거 청크를 얼마나 잘 찾는지 확인한다. 실제 서비스 요청 로그·사용자 질의·운영 인덱스 성능을 평가한 것이 아니다.

청킹은 card → page → section → benefit 계층을 사용한다. card는 본문을 반복한 parent가 아니라 제목·heading 기반의 routing overview다. page와 section은 문단·heading 경계를 우선하고 fixed overlap은 0이다. benefit은 structured label이 가장 관련 있는 raw 문단과 앞뒤 한 문단을 포함하며, 같은 normalized raw 범위를 고른 label은 한 benefit chunk로 병합한다.

Baseline: 세 가지 검색 방법

keyword는 결정론적 토크나이저 기반 BM25 계열 순위, vector는 cache된 질의 embedding과 로컬 Chroma 유사도 순위, hybrid는 양쪽 상위 50개를 RRF(상수 60)로 결합한 equal-weight 순위다.

지표 계약과 분모. baseline은 30개 고정 질의 평균이다. Hit@3은 상위 3개에 expected card 청크가 하나 있으면 1로, 카드 라우팅만 본다. Recall@5은 expected card·expected level·모든 required term을 충족한 relevant chunk 중 top 5가 회수한 비율이다. MRR@5는 첫 relevant chunk의 reciprocal rank(5위 밖이면 0), nDCG@5는 같은 binary relevance를 순위 할인해 ideal DCG로 정규화한다. relevant 계약은 용어 포함 기반이므로 동의어·부분적으로 유용한 청크와 5위 이후 결과를 충분히 평가하지 못한다.

Ablation 설계와 최종 구성

  1. Weighted RRF: vector:keyword 0.5:0.5, 0.6:0.4, 0.7:0.3, 0.8:0.2를 비교했다.
  2. Hierarchy: card, page, section, benefit, section+benefit, all을 분리했다.
  3. Two-stage: card 후보 top N(1/3/5)을 먼저 고른 뒤 section+benefit evidence를 재순위화했다.
  4. Duplicate control: 카드당 최대 1·2개와 parent cap을 비교했다.
  5. Explicit alias metadata: 질의에서 단 하나의 카드 alias만 감지될 때만 corpus metadata로 필터했다.
  6. Final: 0.7:0.3 RRF + unique explicit alias + two-stage N3 + evidence card max 2를 사용했다.
Final 구성. rrf_0.7_0.3_alias_two_stage_n3_card2는 semantic recall을 고려한 vector-forward 0.7:0.3 RRF, 명시 alias가 유일할 때의 metadata filter, 그렇지 않을 때 top-3 card 후보, card intent의 routing, evidence 결과 카드당 최대 2개를 결합한다.

Card Hit@3와 Strict Evidence Hit@3는 다르다

Card Hit@3은 상위 3개에 expected card의 어떤 청크라도 있으면 통과한다. 반면 Strict Evidence Hit@3은 expected card, expected level, required terms를 모두 만족하는 청크가 상위 3개에 있어야 한다. strict relevant chunk가 구성에 없으면 해당 strict 지표는 N/A로 분모에서 제외한다.

카드 혜택 예시. “LOCA LIKIT Eat 음식점 결제일 할인율”에서 LOCA 카드의 다른 안내 청크가 상위 3개에 있으면 Card Hit@3는 pass일 수 있다. 하지만 benefit 계층이며 ‘음식점’과 ‘60%’를 모두 포함한 청크가 아니면 Strict Evidence Hit@3는 fail이다. 카드 식별과 답변 근거 검색을 한 점수로 합치지 않은 이유다.

True two-stage 재평가

기존 ‘최종 2단계’(existing_rrf_filtered)는 전체 RRF 순위를 alias·후보 카드·card cap으로 필터링한 방식이며, 후보 subset 안에서 검색 점수를 다시 계산한 true two-stage가 아니다. 새 true two-stage는 card 10개에 대해 cached vector로 Top-3 후보 카드를 먼저 고르고, 그 카드들의 section+benefit subset에서 vector 거리·BM25·RRF를 실제로 재계산한다.

지표·분모. evidence-only는 card 질문 10개를 제외한 20개 근거 질문만의 평균이며 모든 행의 retrieval 지표 분모는 20이다. strict relevance는 expected card·level·required terms를 모두 만족해야 한다. all 평균은 card 질문 10개의 stage1 순위와 evidence 질문 20개의 stage2 순위를 섞으므로 근거 검색 성능으로 해석하지 않는다. 개발셋에서는 true two-stage 어느 구성도 full vector를 넘지 못했으며, holdout에서 다시 검증해야 한다.

Stage1 병목(30질의 category 평균): proper noun Hit@1/Hit@3 = 1.0/1.0, numeric condition = .9/.9, semantic = .4/.7. 10개 card chunk가 각각 하나라 oracle ceiling은 구조적으로 1.0이며, expected card가 Top-3 밖이면 stage2는 해당 근거를 회수할 수 없다.

해석: broad discovery와 evidence rank

baseline에서 vector는 Card Hit@3 0.9667, Recall@5 0.7250으로 세 방법 중 넓은 후보 탐색(broad discovery) 관점에서 가장 높은 관측값을 보였다. final은 Card Hit@3 0.9000, Recall@5 0.6250이지만 Strict Evidence Hit@3 0.7000, MRR@5 0.6500, nDCG@5 0.6116으로 evidence rank에 더 강한 관측값을 보였다. 즉 이 고정 fixture에서는 vector가 넓게 찾는 후보 생성에, final이 상위권 근거 배치에 적합한 후보라는 해석이 가능하다.

오류·실패 사례. baseline representative evidence에서 “쿠팡과 G마켓 같은 온라인 쇼핑 혜택” 질의의 expected card는 IBK였지만 상위 1~3위가 신한의 온라인 쇼핑 할인 청크였다. 또한 “전월 실적 없이 해외 결제로 마일리지를 더 받는 혜택”의 expected card는 우리였지만 상위 1~3위가 삼성의 해외·무실적 할인 청크였다. 공통 용어·의미가 가까운 다른 카드 혜택이 높은 순위를 차지하는 cross-card 혼동 사례다.

반대로 “나무멤버스 월 이용료를 돌려받는 혜택”은 NH section 근거가 1위였고, “프랜드 주유카드의 리터당 할인 금액”은 KB benefit 근거가 1위였다. 그러나 같은 카드·본문이더라도 expected level 또는 required term 계약을 만족하지 않으면 strict relevance는 false가 될 수 있다. 이는 오류라기보다 계층·용어 기반 평가 계약의 엄격성도 함께 반영한다.

다음 단계

운영 선택 전 별도 holdout 질의 검증이 필요하다. 현재 30질의와 분리된 카드·표현·난이도의 holdout을 고정해 broad discovery(vector)와 evidence rank(final)의 trade-off를 재검증한 뒤 운영 구성을 선택한다. 동시에 visual audit와 corpus 범위 보완, 한국어 형태소·동의어 평가, section-local parent 구조 개선을 검토한다.

최종 결과

계층 청킹 retrieval 본문은 keyword 0.3817, vector 0.5111, hybrid 0.4539의 MRR를 기록했다. 이 비교는 vector·RRF·정규화 ablation이 돌아갈 공통 검색 기준선을 제공했다. 카드 Hit와 strict evidence relevance는 다른 질문을 보므로 한 점수만으로 혜택 근거 성공을 말할 수 없다. 뒤의 정규화·형태소·가중치 실험은 같은 개발 질의와 relevance 계약을 유지해 비교했다.
