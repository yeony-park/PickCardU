실험 1 · 17번 GTE reranker 기본 비교 채택 안 함

왜 이 테스트를 했나

0.4:0.6 RRF가 만든 후보를 GTE reranker가 더 정확히 정렬할 수 있는지 먼저 확인해야 이후의 재채점과 후보 진단의 출발점을 정할 수 있었다. 그래서 무조건 재정렬의 손익을 기준선과 직접 비교했다.

무엇을 확인하려 했나

0.4:0.6·0.5:0.5 RRF와 후보 Top20·Top50의 네 조합에서 GTE를 무조건 적용하고, no-reranker의 Evidence 지표와 비교했다. 후보군에 정답이 없는 경우와 후보 안에서 순서가 잘못된 경우도 함께 구분했다.

결과를 읽을 때 주의

모든 값은 개발 질의 20개의 단일 실행 평균이며, reranker는 저장된 후보 밖 strict 근거를 복구하지 못한다. logit은 확률이 아니고 순서 비교 점수다.

이 실험의 결론. 네 GTE 조합은 no-reranker보다 하락해 현재 채택하지 않는다. strict 손실이 모델 자체인지 계층 중복·평가 계약 영향인지 분리하기 위해 실험 2로 이어졌다.

용어와 실험 계약

저장된 RRF 후보 Top20 / Top50→원본 query + chunk.document→GTE logit→logit 내림차순 재정렬→top-5 평가

reranker는 후보 문서의 순서만 다시 매기는 모델이다. logit은 모델의 비교 점수이며 확률이 아니다. candidate ceiling(후보군 상한)은 후보에 이미 들어온 strict 근거만 재정렬로 회수할 수 있다는 범위다. delta는 no-reranker와의 차이, paired win/loss/tie는 같은 질의의 개선/하락/동률 수를 뜻한다.

입력·실행 계약. 입력은 original query와 chunk.document뿐이며 gold·metadata는 scoring에 사용하지 않았다. model revision 8215cf04918ba6f7b6a62bb44238ce2953d8831c, custom code 40ced75c3017eb27626c9d4ea981bde21a2662f4의 local cache만 사용했다. 실험 2 · 18번 strict 손실과 answer-bearing 재채점 진단

왜 이 테스트를 했나

실험 1의 strict 손실은 정답 문장을 담은 상위 card/page 청크와 strict gold 청크가 갈라진 계층 구조의 영향일 수 있었다. 이 가능성을 확인하려고 정답을 담은 청크군을 묶는 재채점을 추가했다.

무엇을 확인하려 했나

strict 외에 answer-bearing, exact dedup, gold-family 관점에서 0.4 Top50의 GTE 변화를 비교했다. strict 계약의 손실과 실제 답변 문장 정렬 손실을 분리하는 것이 질문이다.

결과를 읽을 때 주의

answer-bearing은 기대 카드와 required terms가 있는 lexical proxy이며 완전한 답변 정답과 같지 않다. gold-family 역시 평가용 oracle이다.

이 실험의 결론. 계층·strict 계약이 손실 일부를 크게 보이게 했지만 numeric 오정렬은 남았다. parent 청크를 제외한 후보 진단이 실험 3으로 이어졌다.
최초 결과와 직접 절대 비교하지 않는다. 아래는 같은 0.4:0.6 Top50 후보를 다른 relevance 모집단으로 다시 측정한 진단이다. answer-bearing, exact dedup, gold-family의 관련 단위가 최초 strict raw와 다르므로 숫자의 절대 크기를 같은 성능 척도로 나란히 해석하면 안 된다.

answer-bearing(답을 담은 후보 진단)은 expected card와 모든 required term을 만족하되 level을 무시한다. 이는 사실적으로 완전한 정답과 동일하지 않은 lexical proxy다. exact dedup은 카드와 정규화 문서가 정확히 같은 청크를 하나로 묶는 방식으로, 327 chunks는 286 groups가 됐고 duplicate groups는 34개, extra chunks는 41개였다. gold-family oracle은 모든 answer-bearing 정답을 한 가족으로 보는 평가용 oracle이며 운영 dedup이 아니다.

현재 계층 청킹에는 exact duplicate와 cross-level containment가 남아 있었다. reranker 없이도 MMR이 상위 Top5의 중복을 줄이면서 검색 품질을 지킬 수 있는지 확인했다.

실험 6 · 20번 선택적 MMR·GTE 결합 상한 지표 trade-off

왜 이 테스트를 했나

실험 4의 유형별 선택 상한과 실험 5의 MMR 진단은 서로 다른 장점을 보였다. 숫자 질의에는 MMR, 의미 질의에는 GTE를 붙이면 이득을 함께 얻을 수 있는지 확인했다.

무엇을 확인하려 했나

gold type으로 selective MMR 및 combined MMR+GTE를 고르고 no-MMR·selective-GTE·selective-MMR와 비교했다. MRR 상승뿐 아니라 Recall과 nDCG guardrail도 판단에 넣었다.

결과를 읽을 때 주의

Top50 λ=.7은 19번 결과 뒤 택한 adaptive post-hoc 조건이고, gold type도 운영 입력에서 알 수 없는 oracle이다. 실제 분류기의 성능이나 운영 지연을 나타내지 않는다.

이 실험의 결론. Combined의 MRR은 올랐지만 Recall과 selective-GTE 대비 nDCG가 떨어져 미승격이다. oracle 대신 실제 정규식 분류기로 같은 선택 논리를 점검한 실험 7로 연결된다.

실험 7 · 21번 실제 정규식 분류기와 GTE/BGE 비교 유망하지만 미승격

왜 이 테스트를 했나

실험 4·6의 oracle 경로는 질의 유형을 미리 알아야 해서 실제 운영 선택으로 쓸 수 없었다. 현재 청킹을 바꾸기 전에, 실제 질문 문구만으로 분류하는 정규식과 두 reranker·입력 형식의 조합을 비교했다.

무엇을 확인하려 했나

고정 0.4:0.6 RRF와 원래 Top50의 leaf_available 후보에서 무조건 rerank와 실제 정규식 선택 경로를 나눠 비교했다. GTE/BGE, 원문(original)/카드명·제목 보강(augmented)이 strict exact·strict raw·answer exact 순서를 어떻게 바꾸는지가 질문이다.

결과를 읽을 때 주의

정규식은 같은 development 질의를 보고 만든 규칙이며 30/30 일치는 unseen 일반화 근거가 아니다. leaf_available 후보 수는 질의별 34~42개이고, 후보 정의와 relevance view가 앞 실험과 다르다.

이 실험의 결론. 실제 정규식+GTE 원문은 strict primary의 개발 후보이고 BGE 보강은 answer-bearing 대안이지만 어느 쪽도 승격하지 않는다. 다음 분기점은 기준선 RRF를 유지한 청킹 변경과 독립 질의 재평가다.

21번 현재 청킹 분기 전 재평가: 핵심 결과 요약

핵심 결과 요약. 현재 안전 기준선은 0.4:0.6 RRF no-reranker(벡터 0.4·정규화 BM25 0.6을 합쳐 그대로 반환)이다. 현재 청킹에서의 운영 후보는 실제 정규식 분류+GTE 원문이고, 모든 질의를 무조건 재정렬했을 때 개발셋 최고는 BGE+카드명·제목 보강이다. 세 결론 모두 같은 개발 질의에서 얻은 것이므로 holdout·운영 승격 결론이 아니다.

무엇을 확인했나. 입력은 0.4:0.6 RRF의 원래 Top50에서 card/page를 빼고 남긴 section·benefit 후보(leaf_available_from_original_top50, 질의마다 34~42개)다. 처리 단계는 (A) 질문 문구만 보는 실제 분류, (B) reranker를 전 질의에 적용하거나 분류 결과에 따라 적용하는 비교이며, 출력은 Top5 검색 순위다. Evidence는 카드 안 혜택·조건 내용 검색, Card는 카드 상품 자체 검색이다.

Phase A — 실제 정규식 분류: 질문을 어디로 보낼지

입력→처리→출력: 질문 문장 → 정규식 분류 → numeric/proper는 RRF 그대로, semantic은 reranker → Top5. 예를 들어 “연회비는 얼마?” 같은 숫자형과 “어느 카드사 상품?” 같은 고유명사형은 RRF, “전월실적 없이 해외 결제 혜택” 같은 의미형은 reranker로 보낸다. 실제 정규식은 개발 30개에서 30/30, sanity 12개에서 12/12였고 gold oracle(정답 유형을 미리 아는 이론상 상한)과 gap 0이었다. 다만 같은 dev 질의를 보고 만든 규칙이므로 unseen 일반화 증거는 아니다.

Phase B — 무조건 재정렬과 실제 선택 경로를 분리

용어: original(원문 입력), augmented(청크 원문 앞에 카드명·제목을 보강한 입력), strict raw(카드·계층·필수 용어를 모두 맞춘 엄격 평가), strict exact-dedup(완전히 같은 문서 중복을 묶은 엄격 평가), answer exact(답 용어를 담은 문서 중복을 묶은 평가), delta(기준 대비 차이), guardrail(함께 지켜야 하는 비회귀 조건)이다. W/L/T는 기존보다 좋아진/나빠진/같은 질의 수다.

최종 결과

현재 안전 기준선은 0.4:0.6 RRF no-reranker다. 실제 정규식 선택+GTE 원문은 현재 청킹의 개발셋 운영 후보이며, BGE 보강은 무조건 재정렬의 개발 신호다. 17번의 GTE 단독 계약은 그대로 보존하되, 뒤의 BGE·MMR·실제 정규식 분기는 다음 독립 검증 후보를 정하는 후속 진단이다. strict와 answer-bearing의 trade-off, numeric과 semantic의 상반된 변화 때문에 어느 결과도 운영 승격을 뜻하지 않는다. 모두 독립 질의·holdout 전의 기록이므로 다음 단계는 청킹 변경 전후를 RRF 기준선으로 분리하고 선택 규칙을 재평가하는 것이다.
