먼저 읽을 점

왜 이 테스트를 했는가

기존 card/page/section/benefit 계층은 한 문장이 여러 청크에 반복돼, 같은 카드의 부모 청크가 검색 상위를 차지할 수 있었다. 중복을 줄이면서도 카드 혜택 근거를 찾을 수 있는지 확인했다.

무엇을 바꿨는가

issuer/card → heading path → direct body 구조로 청킹하고, issuer·카드명·제목 경로를 BM25와 Vector의 검색문에 포함했다. 따라서 순수 청킹만이 아니라 구조 청킹+제목 경로 검색문을 함께 바꾼 묶음 실험이다.

무엇은 바꾸지 않았는가

RRF Vector:normalized BM25 0.4:0.6, k=60, depth=50만 비교했다. BM25는 13번 normalized BM25와 같은 계약이며, IDF는 log(1+(N-df+0.5)/(df+0.5))의 Okapi +0.5 smoothing variant다. 쉬운 말로 드문 단어의 가중치를 계산할 때 0.5를 더해 값이 지나치게 흔들리지 않게 한 방식이다. reranker, MMR, Kiwi 형태소, 질의 router, Chroma query, holdout은 사용하지 않았다.

무엇을 알고 싶었는가

Top3~5에서 카드와 답을 담은 청크를 잃지 않으면서 exact 중복과 계층 포함 관계를 줄일 수 있는지, 그리고 새 구조를 reranker 재평가 후보로 남길 근거가 있는지를 살폈다.

제목 경로가 실제로 기여한 범위

관련 청크 27개 중 6개에서 제목 경로가 required term을 보탰다. 이는 제목이 검색문에 있으면 항상 이득이라는 뜻이 아니다. heading은 실제 결과에 표시되어야 relevance가 정당하며, body가 self-contained answer(본문만으로 답을 설명할 수 있음)를 담는지 별도로 확인해야 한다.

민감한 예: 하나카드의 가맹점 목록은 제목 경로가 `운영경비 5% 청구할인` 맥락을 보탤 수 있지만 목록 body가 대상 가맹점과 조건을 충분히 담는지가 중요하다. 현대카드 대상 표도 제목의 `10% M포인트`만으로는 부족하고, 표 본문에 온라인몰·대상 정보가 있어야 답 근거가 된다.

비교 기준선과 실행·무결성 범위

실험 2 — 현재 프로토타입과 직접 비교

왜 했는가

실험 1의 exact-v1은 내부 공정 비교를 위한 새 exact baseline이어서, 현재 운영 후보와 같은 범위의 후보군인지 별도로 확인할 필요가 있었다. 그래서 결과 후 발견한 baseline 범위 누락을 보완하는 사후 baseline-scope correction(기준선 후보 범위를 맞추기 위한 진단)으로 직접 비교했다.

비교 방식

기존 쪽은 exact-v1 RRF Top50에서 section/benefit만 순서 보존 필터한 현재 prototype 후보(K=30~42)이고, 새 쪽은 structural direct-body Top50이다. RRF 가중치와 기존 순서를 유지했으며 추가 API와 reranker는 사용하지 않았다.

결과와 주의

직접 비교에서도 Evidence Answer Hit@3는 .90으로 늘지 않았고 Answer MRR@5는 .8892에서 .8750으로 낮아졌으며 numeric도 하락했다. semantic은 좋아졌지만 이 관찰만으로 전체 구조 교체를 정당화할 수 없다. formal promotion은 false이며, 원래 formal 기술 gate는 이 사후 비교에 적용하지 않는다.

결론: retain_existing_operational_prototype_baseline_pending_confirmatory_test. 쉬운 말로 현재 프로토타입 기준선을 유지하고 confirmatory test 전에는 구조 청킹으로 바꾸지 않는다. 새 구조는 후속 후보로만 남긴다.

다음 확인

  • 다음 구조 실험 전에 Hit win만으로 통과하지 않도록 stronger gate를 사전 선언한다.
  • 청킹과 제목 경로 검색문의 효과를 분리한 ablation을 수행한다.
  • 현대 연회비처럼 짧은 수치 근거가 Top5 밖으로 밀리는 사례를 별도 fixture로 감사한다.

실험 4 — 새 청킹에서 GTE/BGE reranker 비교

상태: all_query 개발 후보. 새 청킹의 development 30질의 단일 실행 결과이며 운영 승격은 아니다.

왜 했는가

실험 1~3에서 새 구조는 중복을 크게 줄였지만, no-reranker 상태에서는 현재 운영 프로토타입보다 Evidence Answer MRR과 numeric 결과가 낮았다. 새 구조의 카드명·제목 경로·본문 검색문이 reranker(검색 후보를 한 번 더 읽고 순서를 바꾸는 모델)와 결합될 때도 같은 약점을 보이는지, GTE와 BGE 중 어떤 후보가 다음 확인 대상으로 적합한지 확인했다.

무엇을 비교했는가

고정된 0.4:0.6 RRF의 Top20 또는 Top50 후보를 GTE 또는 BGE가 재정렬한 뒤 Top3/5를 평가했다. 후속으로는 원 RRF Top10도 같은 방식으로 확인했다. 전체 적용(all-query)은 모든 질의를 재정렬하고, 선택 적용(semantic-only)은 의미 질의만 재정렬하며 numeric·proper 질의는 RRF 순서를 그대로 둔다. 흐름은 검색 후보 10/20/50개 → reranker 재정렬 → 최종 Top3/5 평가다.

고정·변경 조건

새 청킹 검색 입력은 카드명·제목 경로·본문을 이미 포함한다. 두 모델에는 동일하게 [문서 경로] 발급사 > 카드명 > 제목 경로 + [본문]을 주었으며, gold·평가 label은 입력에 쓰지 않았다. RRF 점수와 reranker raw logit(모델의 정렬 점수)은 섞지 않고 logit으로만 순서를 정했으며 동점만 기존 순위를 사용했다.

실험 5 — 추천형 다중정답 검색 평가

상태: retain_old_selective_bge_development_baseline. 현재 10개 문서 안에서만 보는 closed-corpus(닫힌 문서 집합) 개발평가이며, 시장 전체 추천·상품 variant·발급 가능 여부·개인화 우열은 평가하지 않는다.

왜 이 테스트들이 이어졌나

  1. 여러 카드 추천 평가: 기존 검색과 structural combined 검색의 실제 추천 성능이 어떻게 다른지 물었다. 카드 폭·앞쪽 추천·근거 완결성이 동시에 오르지 않아, 다음에는 후보에 들어온 카드의 근거를 더 잘 묶을 수 있는지 보게 됐다.
  2. 자동 근거 묶음: 같은 카드 안에 흩어진 부모·자식 근거를 자동으로 모으면 조건 증명이 좋아지는지 확인했다. bundle은 일부 회복했지만, 새 표현과 두 조건을 함께 묻는 질의에서도 후보가 충분한지는 아직 알 수 없었다.
  3. 일반화 평가: 표현을 바꾼 질의와 AND 조합에서 후보 누락이 생기는지 점검했다. AND 조합의 후보 상한 하락과 catastrophic loss 때문에, 재정렬만으로 고칠 수 없는 후보 단계의 병목이 드러났다.
  4. oracle 분해: 조건을 완벽히 둘로 나눌 수 있다고 가정하면 후보 합집합으로 회복되는지 살폈다. 회복 가능성은 보였지만 이는 정답 분해를 미리 아는 상한 진단이어서, 실제 문장만 읽는 규칙 분해가 가능한지 확인해야 했다.
  5. 실제 규칙 분해(Follow-up 4): 정답 parent나 카드·순위 정보를 전혀 쓰지 않고 query text만으로 두 조건을 나눌 수 있는지 시험했다. 이 단계가 실패하면 검색·bundle·BGE를 시작하지 않고 안전하게 멈추도록 설계했다.

왜 했는가

앞 실험은 한 질의에서 기대 카드나 답 근거를 얼마나 앞에 두는지에 초점을 맞췄다. 그러나 실제 추천형 질문은 조건에 맞는 카드가 여러 장일 수 있으므로, 새 구조가 정답 카드 폭과 각 카드의 근거를 함께 보존하는지 별도 계약으로 확인할 필요가 있었다.

무엇을 비교했는가

10개 추천 질의와 10개 카드의 조합을 평가했다. gold는 positive 33개·negative 67개이며 insufficient는 0이다. 기존 청킹의 선택 적용 BGE(semantic 질의만 BGE 재정렬)와 새 구조의 전체 적용 BGE(모든 질의를 BGE 재정렬)를 candidate depth D10과 D20에서 비교했다. 새 10질의는 모두 semantic으로 분류돼, 이 범위에서는 selective BGE와 all-BGE가 같은 진단 결과를 낸다.

지표를 쉽게 읽는 법

Card Precision@5는 Top5에 낸 카드 중 정답 카드 비율, Card Recall@3/@5는 정답 카드 중 Top3/5에 회수한 비율이다. Evidence-supported Card Recall@5는 카드 이름만 맞는 것이 아니라 대표 청크 하나가 조건까지 증명한 정답 카드 회수율이고, Evidence Accuracy@5는 Top5 슬롯 중 카드와 근거가 모두 맞는 비율이다. 즉 카드 목록을 넓게 찾는 것과 각 추천이 실제 문장으로 뒷받침되는 것은 따로 본다.

Follow-up 1 — 운영형 card evidence bundle

왜 했는가: 원래 single-chunk 평가는 부모·자식 청크에 나뉜 조건을 대표 청크 하나만으로 증명해야 해서 Q03 근거가 반으로 줄고 Top3 카드 회수도 떨어졌다. 카드명과 혜택 제목을 입력 앞에 붙이는 것은 문맥을 짧게 보강하는 일이고, 여기서의 bundle은 실제 evidence body 여러 조각을 제한된 규칙으로 함께 읽는다는 점이 다르다.

운영에서도 가능한 자동 규칙: 사람이나 gold가 카드를 고르지 않는다. structural Top20의 카드별 최고 RRF seed에서 시작해 node_id/parent_id/heading line 관계를 따라 같은 카드의 1-hop 직접 본문만 모았다. root fanout·재귀 descendant·다른 카드 결합은 금지하고, 최대 5청크·4,096 tokens로 잘랐다. 예를 들어 Q01_C03은 parent direct body를 자동으로 함께 넣어 조건이 나뉜 근거를 한 bundle로 읽게 했다.

정확성도 두 종류로 나뉜다. Card Precision/Recall은 맞는 카드가 상위에 있는지, evidence-supported recall/Evidence Accuracy는 그 카드의 두 혜택·조건을 실제 청크가 함께 증명하는지를 본다. 예를 들어 A카드가 추천 조건에는 맞지만 쇼핑 근거만 있고 통신 근거가 bundle에 없으면 카드 지표는 성공해도 evidence 지표는 실패다. 검색 근거 지표의 상승은 LLM 답변의 factual accuracy 상승을 보장하지 않으므로, 생성 답변은 별도 개발평가가 필요하다.
