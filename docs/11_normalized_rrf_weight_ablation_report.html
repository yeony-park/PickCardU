설계: 사전 고정과 adaptive 후속 탐색

Normalized BM25 Top50+Vector Top50→RRF k=60 · depth=50→fused ranking→Top N reranker candidates

RRF depth 50은 각 retriever의 상위 50개를 융합 점수 계산에 넣는 범위다. 답변에 50개를 반환한다는 뜻이 아니다. fused top N(10·20·50)은 그 융합 순위에서 reranker에 넘기는 후보 수이며, 두 값은 서로 다른 제어값이다.

RRF-only Top5와 reranker Top20은 같은 질문이 아니다. 0.4:0.6은 0.5:0.5보다 Top5 MRR@5/nDCG@5가 높다(0.6200/0.6129 vs 0.6033/0.5966). 반면 reranker 후보 Top20의 strict hit/recall은 0.5:0.5가 0.9500/0.9250으로 0.4:0.6의 0.9000/0.8750보다 높다. Top50에서는 둘 다 1.0000/0.9500으로 같다. accepted run에서 bc_numeric strict chunk는 vector 4위·BM25 44위였고 fused 순위가 0.4:0.6에서 21위, 0.5:0.5에서 13위여서 후자만 Top20에 포함됐다. 반대로 ibk_semantic strict chunk는 vector 44위·BM25 6위였고 0.4:0.6에서 10위, 0.5:0.5에서 12위여서 전자가 Top10에 포함됐다. 가중치는 동일한 depth-50 소스 후보의 융합 순서를 바꾸므로, 0.4:0.6의 BM25 비중이 일부 정답을 Top5에 더 올리는 동시에 다른 일부 정답을 20위 밖으로 밀었을 가능성이 있다. 반대로 0.5:0.5는 Top20에서 더 넓은 정답 후보를 보존한 관측값이다. 이는 기록된 순위와 RRF 구조에 근거한 해석이며, 별도 인과 실험으로 확정된 원인은 아니다.

운영 함의. RRF 단독 Top5를 사용할 때는 0.4:0.6이 합리적인 후보이고, Top20을 reranker 입력으로 쓸 때는 0.5:0.5가 더 안전한 후보이다. Top50 입력에서는 두 가중치의 후보 recall이 같으므로, 성능 상한·비용 비교를 분리해 판단한다.

Metric guide: union은 정규화 BM25 Top50과 vector Top50의 합집합이며 weight별 fused Top50과 다르다. Pass 의미: union strict hit 1.0은 각 질의에 strict ID가 하나 이상 있다는 뜻이다. 핵심 한계: union에 없는 strict ID는 reranker가 복구할 수 없다. 평균 strict recall 0.9667도 모든 strict ID가 항상 후보에 있는 것은 아님을 뜻한다.

다음 판단. 현재 후보군 coverage에서는 baseline 0.5:0.5의 Top20을 reranker 실험 입력으로 쓰는 것이 합리적이다(Strict Hit 0.9500, Recall 0.9250, expected-card Hit 1.0000; evidence 20개). Top50은 성능 상한과 비용 비교용으로 분리한다. reranker는 주어진 후보만 재정렬하므로 union 누락을 복구할 수 없다. reranker가 개선하지 못하거나 후보 누락이 핵심 원인으로 확인될 때 BM25 k1/b를 후속 검토한다.
