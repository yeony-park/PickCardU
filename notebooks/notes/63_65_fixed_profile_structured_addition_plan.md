## 목표와 불변 조건

- benefit/parent-child는 이전에 선택한 각 운영 검색 프로필로 고정한다. 청킹, 임베딩, 가중치, 후보 수, reranker 경로, 근거 묶음과 출력 예산을 재조정하지 않는다.
- QueryPlan/추출 지시/DB60/조회 술어와 gpt-6-luna medium, parser3000/answer2400, 답변 지시·스키마를 고정한다.
- 운영 코드/OCR 검증기/원 PDF·JSON·DB·색인/30~62 결과는 읽기 전용이다. 동의어·오타 사전, 새 DB 열, 구조화 근거 주입, 병렬 검색, 답변 생성 개선은 제외한다.
- SEQ는 S 양성 카드 안에서 원질문 U 한 번, 0건이면 원래 범위 U 한 번이다. 카드 키는 범위 제약, 매칭 사실은 감사 기록이며 별도 전체 U를 합치지 않는다. DB 예외는 정상 0건으로 숨기지 않는다.

## 63: 사후 재평가와 실패 단계 (API 0)

- 62의720행과52의 U/SEQ160행만 재평가한다. 기존 판정과 수치는 보존한다.
- 질문·원문으로 핵심 필수조건과 중요 설명 조건을 먼저 정하고 실제 입력/답변에 결합한다. 이미 알려진 개발 결과의 사후 재평가이지 새로운 독립 검증이 아니다.
- 핵심 완전근거@3, 근거 기반 질문 해결, 중요 설명 조건 충족률(EEC), 오류, 기존 전체 PASS를 분리한다. 추천은 한 카드의 AND 전부, 비교는 요구한 대상·관계 전부가 필요하다. 혜택 성립에 필요한 실적·자격·한도·예외를 부가정보로 낮추지 않는다.
- 원문 정답이더라도 실제 입력 지원이 없으면 source-correct-without-input으로 기록하고 grounded 성공에서 제외한다. 확정불가 질문은 안전한 보류와 잘못된 확정을 별도로 센다.
- EEC 분모는 사전 registry의 실제 선택 카드·혜택 중요조건 전체다. 언급한 조건만 분모로 삼지 않는다. 비교·배제 카드의 주장은 정확성 감사하되 EEC 분모와 분리한다. 0분모는 N/A와 coverage를 보고한다. 선택 카드에 따라 분모가 달라 EEC는 보조 진단이며 개선·비열세 채택 주장에 쓰지 않는다.
- 기존120계획을 추출/DB표현/조회판정/범위/정상0건으로 진단한다. 전체 DB 정확도를 인증하지 않는다.
