# 73 수정 조회와 카드 범위 순차 비교 실행 계획

> 기존 계획을 승인한 사용자 지시와 프로젝트 AGENTS.md에 따라 실행한다.

**목표:** 수정 DB·조회에서 얻은 카드 범위만 비구조화 검색에 적용한 결과를 기존 순차 및 비구조화 단독과 검색·최종 답변에서 비교한다.

**구성:** 70번이 이미 실제 검색한 U/SEQ65/SEQ_REPAIRED의 검색 결과를 검증해 재사용한다. 수정 순차의 실제 검색 결과에는 구조화 suffix가 없으므로 이를 그대로 사용하고, 기존 운영 지시문으로 새 답변을 만든다. 비교 기준 답변은 질문·입력·모델·지시문·출력 한도·반복과 원본 기록을 검증해 70번에서 재사용한다. 71번이 검토한 후보 원문 판정은 질문·카드별 관련성으로 활용하되, 미판정 후보는 자동 정답이나 오답으로 취급하지 않는다.

**환경:** Python 3.12, 기존 운영 검색 프로필·RAG 답변 서비스와 실험 자료, SQLite 읽기 전용, 기존 OpenAI API 사용 승인과 누적 8달러 상한.

**기준:** 이 노트북 실험의 승인된 사용자 요청 및 70·71·72번 보고서/계획.

## 공통 제약
- 운영 코드·원본 PDF/OCR/DB/색인·기존 실험 파일은 읽기 전용이다. Upstage 데이터와 benefit/parent-child 각자의 운영 검색 프로필을 유지한다. Luna 전환은 이후 원본 프로젝트에서 한다.
- 사용자 요청으로 C01/C02/C03/C05/C09/C10/C11/C12/C13/C14/C16/C18 총 12질문×2프로필×2반복으로 축소한다. 짧은 추천·복합 조건·발급사·숫자·지정 카드 상세를 포함한 개발 표본이며 결과를 이미 본 질문이다. 검색 방식은 U·기존 순차·수정 순차. 마지막 방식은 검색 결과의 카드 목록과 비구조화 본문만 쓰며 별도 구조화 사실을 답변에 붙이지 않는다.
- 유료 답변은 새 수정 순차 48논리/최대96물리, SDK 자체 재시도 0, 논리당 최대 2회. 비교 기준 U·기존 순차는 최대96개를 검증해 재사용한다. 70번과 같은 gpt-6-luna·medium·최대출력2400·운영 기본 지시문. 질문별 기준선은 70 실제 요청/응답/해시 확인 후 재사용한다. 모델·질문·프롬프트·프로필·결과 범위 차이를 숨기지 않는다.
- 새 사용량 미확인 시 중단한다. 과거 예약을 포함한 기존 공동 원장을 검증하고, 시작 전에 실제 전체 요청의 보수적 최대 비용을 예약해 누적 8달러를 초과하지 않는다. 요청·응답·사용량을 보존하고 중단 시 동일 identity의 저장분만 재사용한다. 새 임베딩·질문조건 추출·검색 API 호출은 없다.
- 새로운 작업은 73번호 노트북·data·notes와 필요할 때 scripts에만 추가한다. HTML 보고서는 분석자가 결과를 확인해 docs/report/73...html로 직접 작성한다. 기존 사용자 수정 파일은 건드리지 않는다.

## 작업과 검증
- [ ] DB3↔DB5의 행·정규화·70 조회 규칙 차이를 읽기 전용으로 대조하고 실적·한도·범위·AND·0건·일부 후보 누락 사례를 70 저장 검색과 원문 증거에 연결한다.
- [ ] 검색 순위의 고정 평가단위를 질문별 카드로 정의한다. 71 원문 검토의 확인/미확인과 70 전체 방식의 후보 합집합을 결속해 Hit@3·MRR@3·nDCG@3을 계산한다. 미판정 후보를 무관으로 치지 않으며 필요하면 원문을 추가로 확인한다. Recall@3은 해당 질문의 적합 카드 전체 또는 명시된 판정 후보 집합 분모를 제시할 수 있을 때만 보고하고 전체 코퍼스 회수율로 주장하지 않는다. 3개까지만 저장된 결과를 @5로 부르지 않는다. 질문별 승패와 미확정/제외 분모를 기록한다.
- [ ] 기존 U/SEQ65의 실제 요청·지시문과 두 프로필 설정을 검증한다. 수정 순차의 실제 검색 결과가 71 FILTER에 연결되며, 구조화 suffix가 없고 카드/순위/비구조화 본문이 동일함을 전수 검증한다. 위 결과와 원래70 검색 결과를 변경하지 않는다.
- [ ] 고정된 비교 입력·평가 범위·비용 예약을 독립 검토받고 충분한 메모리를 확인한 후 새 답변을 실행한다. 원문과 실제 입력의 확인된 충돌은 그대로 알리고 주결과 및 관련 질문 제외 보조 결과를 기록한다.
- [ ] 보이는 답변 본문·카드별 추천 이유를 원문·실제 입력과 대조한다. 기술실패를 분모에 포함하고, 직접 질문 해결과 실제 주장 정확성을 평가한다. 미요청 조건 단순 생략은 탈락 사유가 아니며 실제 잘못된 주장은 오류로 기록한다. 필요 최소한의 답변 지표만 표준 검색 지표 옆에 둔다.
- [ ] 모든 방식·프로필의 질문별 성패, 자원·시간·비용·오류 사례·원문/OCR 충돌·개발자료 재사용 한계를 직접 확인하여 HTML에 작성한다. 관련 계산과 경계 조건을 테스트하고 등록 reviewer의 독립 검토 및 원본 보존을 확인한 뒤 관련 산출물만 커밋한다.

## 주요 평가 경계
- 기존 71의 source-verified 경로는 반환 후보를 검토한 자료이지 코퍼스 내 모든 정답의 완전한 집합이 아니다. 범위 미확인은 결과에서 구분한다.
- 같은 질문의 2회는 독립 질문 2개가 아니다. 동일 질문·원문 판단으로 짝 비교하며 개발 자료 재사용을 명시한다.
- 기존 70 baseline과 새 순차의 답변은 서로 다른 생성 시점·API 캐시·입력 내용으로 실행됐다. 평균 차이만으로 DB 변경 단독의 인과 효과나 미래 운영의 성능을 단정하지 않는다.
- 검색 시 상위3카드 중 하나만 맞는 Hit는 조건 근거 확보를 보장하지 않는다. 원문에 있고 입력에 없으면 검색/조립, 입력에 있는데 잘못 답하면 생성, 옳은 직접 답의 단순 미요청 설명 생략이면 평가 정책을 점검한다.
