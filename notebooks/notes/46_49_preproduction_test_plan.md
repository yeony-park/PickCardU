**필수 중단 게이트:** 46번 빈 조건 처리·명시 범위 보존·실패 복귀의 필수 회귀가 하나라도 실패하면 후보를 다음 단계 통과 상태로 취급하지 않는다. 47·48은 오프라인 문제 진단만 허용하고 추가 유료 실행·49 확인·운영 이식 적격 판정은 중단한다. 알려진 의미 오류의 잔여 위험과 처리 방침도 공개하고 확인 전 계약에 기록한다.

**Tech Stack:** 기존 Python 환경, 운영 QueryPlan/검색/답변 구성요소의 읽기 전용 참조, 기존 SQLite·청크·검색 인덱스, 기존 API 호출·캐시·사용량 기록 방식, notebook 중심 실행·검사, 필요한 경우에만 pytest, 직접 작성하는 HTML 보고서. 새 프레임워크·문서 임베딩·전역 환경 변경은 계획하지 않는다.

## Global Constraints

- 사용자 승인에 따라46~49를 순차 실행한다. 새 API 사용료는 실패·재시도를 포함해 합계8 USD를 상한으로 하며 요청 전에 보수적으로 비용을 예약한다. 운영 코드·운영 DB·활성 인덱스는 변경하지 않는다. 응답시간은 실측·비교하며 별도 운영 SLA는 확정하지 않는다.
- 폴더 기준은 [노트북 폴더 구성](NOTEBOOK_LAYOUT.md)을 따른다. notebooks/ 최상위에는 번호가 있는 .ipynb만 작성하고, 계획·설명은 notebooks/notes/, 입력·원응답·캐시·결과는 notebooks/data/<번호>_<실험명>/에 둔다. HTML 비교 보고서는 docs/report/<같은 번호>_<실험명>_report.html에 두며 대응 노트북 번호와 일치시킨다. 아래 경로에 실험 파일·폴더를 생성한다.
- 새 실험은 노트북 안에서 단계별 실행·체크포인트·재개·평가·표시를 구성하고 기존 코드를 우선 재사용한다. 실험마다 별도 실행기·평가기·감사기·공통 모듈을 일괄 생성하지 않는다. 반복 재사용이나 외부 자동 회귀 검사 등 노트북 밖 코드가 필요한 이유가 구체적인 경우에만 최소 helper/test를 notebooks/scripts/에 만들고 책임과 필요성을 노트북에 적는다. 별도 .py 파일은 현재의 확정 생성 목록에서 제외한다.
- 결과 HTML은 main Codex가 실제 결과 JSON·원응답·원문 근거·질문별 승패를 확인하고 해석한 뒤 직접 작성한다. HTML 생성기, Markdown→HTML 변환기, 자동 보고서 렌더링 코드를 새로 만들거나 새 보고서 작성에 사용하지 않는다. 수치 집계·표와 원자료의 일치·링크 검사는 가능하나 보고서 본문을 자동 생성하는 근거로 삼지 않는다. 기존 생성기는 이번 작업에서 삭제하거나 수정하지 않는다.
- 폴더 이동으로 경로·코드 해시가 달라진 기존 실험은 당시 봉인 기록을 덮어쓰거나 검사 우회로 재실행하지 않는다. 새46~49 계약은 현재 scripts 경로·현재 코드 해시와 기존 자료의 출처를 명시한다. 과거 저장 출력을 폴더 정리 이후의 새 실행 결과로 취급하지 않는다.

- 청킹은 운영 benefit/parent-child 구현을 사용한다. 순수 청킹 효과와 프로필 전체 효과를 혼동하지 않는다. 기본 후보는 benefit이며 각 실험에서 두 프로필 결과를 분리한다. 조건 추출 실험은 청킹과 독립적이므로 중복 호출하지 않는다.
- 새 실험은 순차 실행한다. 기존 가중치·검색 깊이·재정렬·top3·카드별 최대5개 근거·64000 UTF-8 bytes·답변 모델/추론/2400 출력 설정을 별도 목표가 아니면 고정한다. 대규모 파라미터 탐색은 하지 않는다.
- 원질문을 항상 보존한다. 구조화 결과는 사용자 요구를 추가·변경하거나 같은 카드의 다른 서비스 조건을 섞는 근거가 될 수 없다. 명시 카드 범위는 이미 신뢰할 수 있게 식별된 경우에만 강제하고 임의 복원하지 않는다.
- API 원응답·전체 시도·실패·전송/캐시 토큰·사용량 비용·실행 시간·최대 메모리를 기록한다. 청구서 비용과 Codex 검토 비용 등 미측정 항목을 구분한다. 향후 유료 실행 전에 각 실험의 호출 상한과 재개 정책을 봉인한다.
- 각46~49 단계 첫 산출물은 해당 data 경로의 `execution_manifest.json`이다. 질문ID·원문/주석 해시·유형·설정·프로필·반복 수·논리 평가 행 수·parser/임베딩/검색/재정렬/답변의 최대 호출 수·전체 물리 재시도 상한·USD 비용 중단 한도·중단/재개 규칙·코드/자료 해시를 숫자와 함께 실행 전에 고정한다. 대상 질문이나 설정을 결과 확인 후 늘리지 않는다. 아직 정하지 않은 자원 한도가 있으면 파일을 승인된 실행 계약으로 취급하지 않고 유료 실행하지 않는다.

- 오타는 문맥으로 명확한 경우와 여러 해석이 가능한 경우를 구별한다. LLM이 보정할 수 있다는 가능성을 보정 보장이나 실측 정확도로 바꾸지 않는다.
- 45번은 검색 이후 근거 재구성 실험이었다. 48번은 원질문 검색을 유지한 검색 단계의 보조 실험이며, 답변 근거 교체·LLM 해석 문제도 재발할 수 있다.
- 41·42번의 Q_EXPAND_U는 질문에서 추출한 조건·고정 별칭으로 검색 표현을 보강한 기존 비교다. 48번은 DB에서 실제 일치한 혜택·조건을 사용하고, 동일 카드 범위의 원질문 검색과 별도 보조 검색을 통합한다는 차이를 명시한다. 기존 표현 보강 실험을 미실행으로 취급하지 않는다.
- 핵심요구 PASS와 전체 주장 정확성은 별도다. 검색 Hit/조건 근거 포함률이 늘어도 새 잘못된 혜택·조건·인용·중요조건 손실이 생기면 개선안을 선정하지 않는다.
- 구조화 정보 사용으로 제외된 정답 카드는 답변 검증으로 복구할 수 없다. 후보 범위에서의 손실과 답변 설명에서의 손실을 별도 측정한다.
