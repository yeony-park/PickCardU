# 60~62 검색 보완과 효과 검증

2026-10-24 사용자 계획 승인 및 구현 지시. 계획 독립 검토는 등록 proposal-reviewer가 기존 SEQ 답변 대조군 추가 후 Blocking/Major 0으로 수락했다.

## 목표·불변 조건

- 구조화 DB/술어/범위의 확인된 문제를 교정하고 U, SEQ_BASE, SEQ_REPAIRED를 비교한다. 성과를 보장하지 않으며 불충족은 불채택한다.
- 모델 gpt-6-luna/medium, parser3000/answer2400, 운영 두 청킹 프로필, top3, 카드당 근거5, parent묶음5, 64000bytes를 유지한다.
- 운영/OCR 검증기/원본PDF·JSON·DB·색인/55~59 원자료와 코드는 변경하지 않는다. 기존56DB의 새복사만 database-manager가 변경한다.
- 새 컬럼·별칭 사전·동의어/오타 보정·답변 프롬프트 변경·조건 문단 추가는 제외한다. 기차/철도는 구조화에서 합치지 않는다.
- 구조화 결과가 있으면 해당 카드 안에서 원질문으로 U1회, 0건이면 원범위 U1회. U 대조군은 독립 비교군이며 SEQ에 전체U를 합치지 않는다.

## 순서

1. 60A: 명시 무실적 복합문구, 명시 무료이용/입장, 대상 괄호/병렬 표면정규화, 카탈로그 기반 원범위를 보완한다. unknown 일괄0 금지. 무료서비스는 kind=None/status=true로 표현 가능할 때 any만 통과하며 discount/earn으로 오분류하지 않는다. 모호한 카드는 임의 선택하지 않는다.
2. 60B: 59의32질문/96계획과 새범용8질문/24계획(합40/120)을 고정한다. 같은 계획에서 DB2종×술어2종×원범위2종=8조합, 총960논리 SQL을 비교한다. 수동 정답조건은 실패 원인 진단 전용이며 실제 검색/답변 입력에서 제외한다.
3. 61: 세군에 보완 원범위를 공통 적용한다. U/SEQ_BASE(DB56+기존술어)/SEQ_REPAIRED(DB60+보완술어)×40×2profiles×3=720검색. SEQ_BASE는 공정비교용으로 범위가 공통보완됐으므로 과거59 그대로의 재실행과 구분한다.
4. 세군의 실제 상위카드 union 원문을 감사해 질문·카드별 직접요구/중요조건/불확실 기준을 답변 전 동결한다. 참조 외 유효 대안을 허용하며 관계가 불명확한 입력은 지원으로 세지 않는다.
5. 62: 안전성 검사 후 동일 기존 답변지시로 세군×40×2profiles×3=720논리답변, 각최대2시도/물리최대1440. 같은반복의 동일요청만 출처결속 후 재사용하고 반복간 재사용금지.59응답 재사용은 model/reasoning/instructions/input/schema/2400 및 해당반복 일치 검증이 필요하다.

## 평가·선택

- 명시 조건30, 범용8, 확정불가2를 구분한다. 기존32는 결과가 알려진 개발질문이며 새8도 같은106문서의 개발평가다. 새문서/독립사람/맹검 검증이 아니다.
- 검색 주지표: 실제Top3중 동일한 유효카드1장의 직접요구 및 중요적용조건 전부가 실제 입력에서 지원되는 질문 비율. 카드별 중요조건은 원문으로 고정하고 다른카드·다른혜택의 값을 대신 쓰지 않는다. 부분조건/불확실/기술실패는 완전근거 성공이 아니다.
- Hit@3/MRR@3은 객관적 원문관련성을 검토하는 기존양성30에 적용, 범용8/확정불가2는순위지표N/A. 질문별근거회수·입력조건반영·최종PASS·잘못된추가주장·범위/관계오류를분리한다.
- 각profile별 SEQ_REPAIRED의 명시30 완전근거는 U보다 높고 SEQ_BASE보다 낮지 않아야 한다. 명시30/범용8/전체40 PASS는 두대조군에각각비열세,확정불가2의잘못된확정증가없음,카드Hit/MRR비열세와새범위/혜택관계회귀0를요구한다. 집단/프로필퇴행을전체평균으로상쇄하지않는다.
- 기준SEQ대비상승없으면 DB정합성교정과품질개선주장을구분한다. 원문불확실/미판정/미실행은성공으로채우지않고선택금지한다.
