# 72 · LLM 근거 전달 형식 비교

승인된 계획을 실행한다. 검색 개선 실험이 아니라 고정 검색 결과의 전달 방식과 생성 품질 실험이다. 운영 코드와 원본·기존 실험은 읽기 전용이다.

## 범위와 고정값
C01/C10/C12/C13/C14/C16/C17/C18, benefit 및 parent-child 운영 프로필. 70번 SEQ_REPAIRED의 검색 r2를 하나의 스냅샷으로 사용한다. 카드·순위·원질문·비정형 본문·eID·구조화 행·순서를 그대로 둔다. 새 조건 추출/임베딩/검색은 없다. 모델 gpt-6-luna, 추론 medium, 출력2400, 동일한 운영 지시문과 공통 형식 안내를 사용한다. 사용자 선택은 핵심8질문 우선이다.

## 비교 조건
- A: 전체 canonical JSON. card_key/fact_id/source_relative_path만 C/F/P로 일대일 치환한다. 70번 전송 문자열 그대로는 아니다.
- B: 동일 행의 비어 있지 않은 업무10필드와 해석5상태를 간단한 JSON으로 전달한다.
- C: B와 같은 정보·순서를 한국어 라벨과 원래 값의 텍스트로 전달한다. 여러 줄은 들여쓰기로 구분하고 정확한 역변환을 검사한다.

A/B는 전체 필드와 최소 업무 투영의 결합 효과다. 단순 추적 필드 삭제만의 효과가 아니다. B/C가 동일 정보의 표현 비교다. 카드명·발급사는 공통 카드목록으로 묶지만 원래 본문이나 업무값의 반복은 수정하지 않는다. 새 수치 요약이나 관계를 추가하지 않는다.

## 컬럼 구분
LLM 전달: documents.card_name/issuer_name, facts.target_raw/action_raw/benefit_type_raw/value_raw/unit_raw/condition_raw/cap_raw/period_raw/frequency_raw/exceptions_raw. 빈 업무값은 그 행에 미기록임을 안내한다. 추가 해석상태 action_status/percent_state/spend_state/cap_state 및 derived.cap_period_state는 미확인 보존용이다.

서버 보존: document_id/fact_id/ordinal/provider와 원문경로·SHA·페이지수·행수·raw_json/derived_json·field_evidence/relation_scope·요구조건 연결·정규화 사유. 중복 정규화 숫자는 B/C에서 제외하며 원래 업무문자열을 유지한다. C/F/P와 eID는 짧은 참조이고 서버에서 원래 소유자와 출처로 복원한다. 적용 관계 자체는 추적 정보와 다르므로 업무 원문 또는 같은 카드 U에 남아 있어야 한다.

## 사전 검사와 중단 기준
실제 모든 추가 행의 현재 DB5 SQL raw10과 canonical.fields를 대조한다. 오래된 raw_json으로 재구성하지 않는다. B/C 필드·상태·소유자·순서 및 텍스트 역변환을 검사한다. C12 D4의 월/건 표제가 같은 카드 U와 원문에 있는지, C18 할인 전 이용금액 한정어가 보존되는지 수동 점검한다. 관계를 해결할 수 없으면 유료 실행 전체 보류한다. 기존 source gate와 source_review를 보존/검증하고 이번 실제 행을 별도로 점검한다.

## 실행과 비용
8×2×3형식×3생성반복=144논리 답변, 최대288물리 호출. 반복별 ABC/BCA/CAB 순서를 순환한다. SDK재시도0, 기존 기술검증 최대2회만 허용한다. 과거 응답을 재사용하지 않는다. 같은 identity의 중단 재개만 허용한다. API 호출 원본과 사용량을 파싱 전에 기록한다.

누적상한8달러, 시작 누적차감2.570097960달러. 실제 요청 전체를 UTF8 바이트 상계+8192 여유와 최대출력으로 계산하고 288회 전체 예약이 잔액에 들어오는지 먼저 확인한다. 새 사용량 미확인 발생 시 중단하고 기록을 보존한다. 단가는 기존 실험 동결 기준이며 실제 청구액이 아니다. 요청/캐시/출력토큰·비용·재시도 포함 답변준비 평균/P95·CPU/RSS를 기록한다. TTFT·화면표시·온라인 전체시간은 미측정이다.

## 평가와 선택
66번 정책: 기술성공 AND 직접요청 해결 AND 실제 보이는 본문/추천이유 주장의 원문 정확성. 묻지 않은 조건 생략만으로 실패시키지 않는다. 숨은 claims로 정답을 보충하지 않는다. 입력 지원과 원문 사실 정확성은 별도로 판정한다. 실제 의미 판정은 Codex 수동 검토이고 코드가 정답을 자동 판정한다는 뜻이 아니다.

71번 질문 필수단위를 사용한다. 형식별 분모24답변/프로필, 기술실패 포함. C18 원문150만원/OCR50만원 충돌은 세 조건에 유지하며 전체8질문 주결과와 C18제외7질문 민감도를 함께 보고한다. 별칭 화면누출은 별도 형식오류와 후보선택 거절기준이며66 PASS 정의를 바꾸지 않는다.

A대비 질문별3회 PASS수가 줄지 않아야 한다. 직접요청/실제주장정확성 합계가 낮아지거나 확인된 오답 수가 늘거나 A에 없던 질문·오류유형이 새로 생기면 선택하지 않는다. 별칭누출 없음, clean7 방향 역전 없음도 요구한다. 통과 후보는 PASS→입력토큰→평균답변준비시간→동률B 순서다. 품질동률의 자원개선은 효율후보라고만 부른다. 통과후보가 없으면 A 개발기준 유지, 운영반영 없음. 8개는 개발 선택용이며 독립 확인시험이 아니다.
